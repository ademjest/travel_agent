# Web 按聊天窗口统计模型用量

日期：2026-10-19

## 功能

聊天区顶部新增可展开的“本会话用量”。默认显示当前聊天窗口的累计已知 token、模型调用次数、估算费用和进行中的调用数；展开后显示：

- 输入 token。
- 缓存输入 token（已包含在输入总量中）。
- 输出 token。
- 推理 token（供应商按 Chat Completions usage 统计时已包含在输出中）。
- 按用途和模型分组的调用次数、输入/缓存/输出及费用。
- usage 缺失、历史费率回算和缓存拆分缺失提示。

会话统计随既有消息和上下文轮询自动更新，任务进行中更新较频繁，空闲时沿用已有刷新周期。切换窗口时先清空旧统计，迟到的旧请求不会覆盖新会话数据。新建但尚未创建服务端会话的欢迎页不显示统计。

## 统计口径

1. 总 token = 已知输入 + 已知输出；不额外加缓存输入和推理 token，避免重复计算。
2. 模型调用次数包含解析、规划、摘要、修正等实际请求，一条聊天消息可能对应多个模型调用。
3. 失败和重试的请求同样计入调用次数；有真实 usage 时计入 token，没有 usage 时保留未知，不猜测为零。
4. 进行中的请求显示进行中状态，只有已返回的 token 进入已知合计。
5. 费用复用服务配置中的费率、快照、历史回算和多币种拆分规则。已知费用与未知费用数量同时显示。
6. 服务连接测试、其他聊天会话、QQ 调用不纳入当前聊天窗口。
7. 会话统计针对本地仍保留的调用明细，不是永远不变的账单。现有数据保留策略清理明细后，历史统计范围相应缩小；删除会话后该会话统计也不再提供。
8. 统计直接读取本地数据库，不为展示统计发起新模型请求。

## 后端

新增 `conversation_usage_report`，复用现有聚合函数和费率说明。选择模型调用时：

- 精确匹配 `web:group:<conversation_id>:` 的事件前缀，保留冒号边界，防止相似 ID 串算；旧版缺少 job_id 的记录也能归属。
- 同时纳入 job_id 指向当前 Web 会话的任务调用，支持非普通消息事件名的关联任务。
- 两个条件合并为一次行选择，满足两个条件的调用不会重复计算。
- 在会话上下文响应中返回 `model_usage`，没有模型配置或没有调用记录时返回零统计。
- 沿用会话存在性、删除屏障和访问校验，统计前后确认会话可用；不存在、已删除或未认证的请求不能读取数据。

无需新增数据库表、迁移历史对话或增加独立的前端轮询接口。服务配置中的全局用量继续保留。

## 前端

新增 `ConversationUsage` 组件，嵌入当前聊天区域。简要信息常驻，详细内容按需展开；窄屏时明细表可横向滚动。显示器不够高时明细区内部滚动，保留消息和输入区空间。

`Context.model_usage` 为兼容字段。切换会话后立即重置上下文，且组件再次检查返回的 conversation_id，防止短暂展示上一窗口的费用。

## 改动位置

- `infrastructure/model_gateway.py`：可复用的指定行聚合、会话费用报表。
- `infrastructure/web_repository.py`：上下文挂载当前会话的用量。
- `frontend/src/api.ts`：统计结构。
- `frontend/src/ConversationUsage.tsx`：窗口统计展示。
- `frontend/src/App.tsx`、`frontend/src/styles.css`：接入、布局。
- `tests/test_conversation_usage.py`、`tests/test_web_app.py`：隔离、刷新、访问和费用统计测试。
- `frontend/src/ConversationUsage.test.tsx`、`frontend/src/App.test.tsx`：展示、切换及迟到响应测试。

## 建议的成本控制对比测试

1. 新建两个独立窗口，分别使用改进前、后的配置，并确保模型、供应商费率、初始记忆和工具数据条件可比。
2. 在两个窗口发送相同的一组测试请求，等待每个请求结束。
3. 比较总 token、费用及模型调用次数；展开明细观察解析、摘要、规划各自开销。
4. 同时观察缓存输入差异。缓存命中受供应商和请求时机影响，不宜将单次缓存差异全部归因于代码优化。
5. 若存在未返回 usage 或费率未知，应将本轮标为统计不完整，避免用不完整费用判断优化收益。

人工验收：新会话显示零统计；回复完成后自动更新；切换窗口不串算；刷新或重新启动后从本地记录恢复；服务配置连接测试只增加全局用量。
