# 2026-11-22 酒店处理与多方案增强

本次分支 `hotel-update-and-multiplan-enhancement` 基于已通过 [PR #6](https://github.com/ademjest/travel_agent/pull/6) 合并的 main，公开同步本地酒店、多方案与整体改期增量；尚未将本分支合入 main。此前铁路 MCP、双路规划、多供应商模型与 CI 修复见 [2026-11-09 更新记录](2026-11-09.md)。

## 主要更新

### 酒店目标接续与预算准入

- 引用行程草案查价可继承展示中的酒店候选、城市/地址、预算及有证据的入住信息；确认过期不删除这些只读输入。房间数和儿童情况不凭空默认，旅行日期只形成待确认的住宿日期提议。
- 新增受限住宿目标入口，复用既有 Agent 循环和唯一酒店查价执行器。模型根据原店结果决定后续核价、替代搜索和住宿预览，代码核对归属、版本、品牌、预算及来源限制。
- 有预算时，主推荐仅接受适用且可比的来源报价；地图消费、起价、均价、约价、其他日期或税费不明金额不能冒充预算内房价。缺价对象保留为调查候选，不误判为超预算或无房。
- 明确指定门店时保留指定；明确只读时不开放替代预览。普通草案引用不等于锁定名单，明确品牌/集团由服务端约束后续搜索。
- 调用、预算、未知结果和取消保护继续生效；同一住宿运行最多两个不同的问道提交步骤，步骤由规范化请求和目标版本绑定，不按模型临时调用 ID 增加额度。
- 已取得有效结果形成候选集合预览后结束该轮工具调用；正式保存仍走原确认事务，不订房、不付款。

### 原文参考价格展示

- 增加纯本地价格摘要，聊天和行程面板可直接展示来源中的起价、约价、床位价和原文总价，同时保留酒店归属、原文位置与阅读入口。
- 不把停车、早餐、押金等附加项当作房费，不补造逐晚同价、税费、币种或总金额；对应关系不明或来源缺价时保留待核对状态。
- 首轮需要住宿的行程草案可附参考价；入住条件不完整时不必先发送第二条查价命令，也不虚构人房信息。参考模式与完整报价的缓存指纹分开。
- 参考摘要用于阅读，不放宽完整报价、预算或推荐准入。城市行程可先形成明确注明住宿待核价的草案；明确要求预算内替代的住宿目标不能因此被标记完成。
- 查看旧原文、只读比较和确认保存不重新查询供应商；新摘要不批量改写历史消息或正式行程。

### 多方案、历史另建与引用续接

- 区分从头新建、基于引用版本另建、继续当前操作。服务端在入队时冻结目标、草案修订及续接凭据；模型不能提供所有者、任务 ID 或完整快照来扩大授权。
- 从不可变消息回执读取历史方案，生成独立身份后应用增量修改；保留原方案、证据时间与已有要求，不复制旧确认资格或提醒授权。
- 编辑焦点明确绑定一项操作；同会话多个草案、引用与显式编号冲突、版本变化或缺少引用时补问或拒绝，避免自动选错方案。
- Web 显示稳定短编号、保存状态和草案修订，增加独立新建、历史另建、切换/结束操作及刷新后的继续入口。
- 允许只读并排比较两份当前展示方案的日期、要求、景点和住宿候选；不会重新查价或修改任一方案。
- 补问转候选、精确保存、放弃和针对旧残缺任务的接续沿用现有事务、幂等与归属检查，没有新数据库表或并行保存通道。

### 改期与意图可靠性

- 整体改期统一更新旅行范围、每日活动、规划窗口与已声明的往返日期，保留出发/到达时段语义，避免旧交通日期覆盖新日历。
- 已购票不自动改签；新范围改变天数时明确要求重新规划。旧车次、报价和预约资料不能直接充当新日期的已核实依据。
- 预览不修改提醒；确认后仅处理实际关联的提醒，普通绝对时间提醒不随行程移动。
- 区分模型输出截断、过滤、无效 JSON、业务合同、超时及预算阻断。仅明确截断允许一次有预算约束的输出扩展；各类修复与旧模型回退不叠加成多重重试。

## 存储与升级

问道非研究请求的回执由 `(event_key, purpose)` 扩展为 `(event_key, purpose, step_key)`，增加 `run_key`。迁移在事务中保留旧 JSON、索引和空步骤兼容，并支持异常回滚。新代码按精确步骤读取原文，避免同一事件多份资料随机取第一份。

1. 停止自己的后端，备份 .env 与业务数据目录；Web 默认数据目录为 `data/web`。
2. 更新本分支源码，沿用 Python 3.11、Node.js 24 及现有依赖安装命令；在 frontend 执行 `npm ci`、`npm run build`。
3. 保留现有配置和数据，启动新版让兼容迁移完成。模型、问道、地图及铁路继续使用部署者自己的凭据和额度。
4. 有新步骤回执后，不能简单回退旧主键或用旧数据库覆盖后续数据；回退须保留已新增记录及相应读取兼容。
5. 冻结的旧操作若提示资产、来源或目标版本已变化，保留历史结果并核对后重新发起，不自动重放未知调用。

本次没有增加新供应商接口、Agent 框架或提示模型阶段。参考价格、真实可售房价、税费、库存和最新政策仍以供应商实际返回与独立核实为准。

## CI 修复与验证范围

本地测试模块直接导入了 TripTests 类，导致 unittest 重复收集 36 项。现改为模块方式复用夹具：发现数和唯一测试数均为 2088，所有原有唯一 ID 保留，Windows 分片重复检查保持启用。

本次发布将检查完整后端、任务场景、只读事实、架构、前端测试和生产构建，并保留 Windows 四分片及汇总的完整覆盖校验；对应云端最终结果以本分支提交的 Actions 为准，不以局部通过代替整套结论。测试与部署检查不调用真实模型、问道、地图或铁路，也不启动 run_web 或读取正式业务数据库。

发布文件只包含源码、静态数据、必要夹具、使用指南和发布记录。docs 继续仅保留 guides/releases；运行摘要正文在 prompts/conversation_summary.md，摘要回归输入在 tests/fixtures/。内部方案、浏览器录制与截图、真实配置、数据库、附件和实验日志不上传。
