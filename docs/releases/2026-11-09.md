# 2026-11-09 核心能力与可靠性更新

本次在 `data-update-and-reliability-control` 分支追加同步当前本地源码，延续 [2026-10-23 版本](2026-10-23.md)，未合并主分支。项目概览见 [README](../../README.md)，日常操作见 [Web 指南](../guides/web.md) 和 [QQ 指南](../guides/qq.md)。此前功能与基础部署说明见 [2026-10-19 更新记录](2026-10-19.md)。

## 主要更新

### 铁路 Remote MCP 与行程交通

- 通过 MCP Python SDK 接入 HTTPS Remote 铁路服务，支持 Streamable HTTP、SSE、可选 Bearer 鉴权与连接合同检查。
- 查询指定城市或车站、日期、时段和车种；结果卡展示实际取得的席别、参考票价、余票与数据时间，支持分页、本地筛选和明确发起的新查询。
- 往返交通参与首末日可用时间计算，区分出发和到达约束、自然日及完整游览日；席别或返程局部修改保留未受影响的景点和交通。
- 未开售、空结果、查询失败和候选截断分别展示；不自动购票，不保证城市站点覆盖或余票持续有效。配置与接口边界见 [铁路指南](../guides/rail-mcp.md)。

### 双路规划与研究资料

- 启用问道且符合完整规划条件时，高德资料草案与问道草案有界并行生成，再经选择或融合、地点与约束校验；有效单路结果可作为降级依据。
- 保存两版输入和比较结果，支持从聊天或行程面板查看本轮草案；局部修改与采用已有方案不强制重跑完整双路流程。
- 改进景点与子场馆分组、重复目标处理、来源偏好接续，以及官网身份、访问状态和候选入口的分层展示。
- 问道资料支持列表、加粗字段、编号标题与续行；文化介绍、票种、电话、建议时长及预约字段保持边界和原文来源。研究报告、规划输入与行程表达共享文化资料状态，资料不足或歧义不补造为已知。
- 供应商综合回答和模型比较理由不等于官方核验；票价、开放和预约仍保留日期、人群、产品范围与待核实项。官网入口说明见 [官网查询指南](../guides/official-links.md)。

### 独立酒店查价与预算筛选

- 新增统一 `query_hotel_prices`：无需先创建行程，允许先找候选、选定门店，再补齐入住/退房、人房数、儿童年龄与房型条件。
- 查询、主动刷新和历史资料读取分开；适用缓存、分批续接、候选按钮、日期提议、失败更正及重启恢复复用原任务和持久回执。
- 门店、日期、产品、价格口径、税费与原文引文分别校验。区分明确来源报价、参考线索、缺价、提取失败、供应商未完成和预算阻断，不以起价、约价、人均消费或早餐价格替代指定住宿房价。
- 明确品牌/集团和可比预算优先于档次、距离等排序；品牌目录仅包含已登记参考条目。缺价酒店保留为待核价候选；餐饮支持人均预算边界和单餐调整。
- 已有报价可进入住宿修改预览，确认后保存行程；查价不订房、不付款。问道缺少房型、税费或房态时继续标注未知，不承诺任何日期都能取得完整报价。

### 消息引用、草案接续与展示

- 引用指定消息读取当时的不可变快照；澄清和局部修改继续对应任务，写入仍校验当前草案和正式版本，避免将历史回复当作新的执行授权。
- “重新核对”“保存这版行程”“放弃草案”绑定明确对象、修订和稳定请求号；确认资格过期后内容仍可查看和核对，旧确认不能直接保存。
- 重核保留未保存修改，按需检查过期交通及冲突；保存已展示候选不会重新完整规划。放弃操作继续受取消和迟到提交保护约束。
- Web 增加铁路卡、往返交通卡、酒店选择卡、两稿比较及独立用量面板；拆分消息提交和会话管理逻辑、布局与内容样式，保留 Markdown 与 LaTeX 展示。

### 多供应商模型与预算账本

- 模型配置分为连接、模型档案和用途分工：基础、常规、复杂及可选视觉；保留明确的原用途覆盖。当前协议仍为 OpenAI-compatible Chat Completions。
- 兼容旧模型环境字段；显式保存后采用版本化 `LLM_CONFIG_JSON`，整体选择配置来源。密钥不回显，更换地址需重新提供凭据，参数及能力按档案声明和显式测试处理。
- 调用记录保留连接、档案、实际模型、请求身份、提示资产和费率快照；按用途、会话、消息及币种展示用量与费用依据，不自动换汇。
- 已结算且用量有效时按实际消耗计算占用；未知、未完成和旧记录继续保留预留。明确开始新一轮酒店核价可建立关联运行，日/月限额及未知费用保护继续生效。
- 模型探测与供应商测试仅由用户显式触发，可能产生费用或额度消耗；配置保存后重启使 Agent 采用新设置。详见 [模型配置](../guides/web.md#多供应商模型配置u6)。

### 模块与验证入口

- 业务集中到 `tools/`，请求路由与上下文归 `app/`；工具目录明确 owner、参数合同及资源权限，原领域服务入口退役。
- `MemoryStore` 管理连接及仓库组合；内部集成使用 `store.delivery`、`store.documents`、`store.conversations` 等显式仓库，旧存储转发接口不再保留。
- Skill manifest 管理 20 个模型阶段，登记文本、资源、合同和内容哈希；请求冻结资产，不能使用变化后的资产自动续传旧调用。维护说明见 [Skill 指南](../guides/skills.md)。
- 评测统一为 `scripts/run_evaluations.py`，历史专项脚本归档到 `scripts/archive/2026-10`。旧脚本内的历史授权不构成新的付费调用许可。
- 发布检查统一记录源码、提示资产、语料与结果指纹；GitHub Actions 使用相同入口。日志增加安全元数据、UTF-8 轮转和明确时区。

## 新用户部署与可选配置

使用 Python 3.11 和 Node.js 24，按 README 安装依赖、构建前端，再运行 `python run_web.py`。Web 不要求 QQ 在线、NapCat 或 Docker。首次缺少接口配置仍可打开页面，对应能力需配置后使用。

| 配置 | 用途与默认边界 |
| --- | --- |
| 模型连接与档案 / 旧 `LLM_*` | Web 表单配置新分工；旧字段兼容，显式保存后新配置块成为唯一模型来源 |
| `AMAP_API_KEY` | 地点、市内交通与路线资料 |
| `SEARCH_API_KEY` | Tavily 搜索；官网身份和事实证据另外校验 |
| `WENDAO_API_KEY`、`WENDAO_ENABLED` | 问道资料与完整规划分支；默认关闭，需有效凭据与额度 |
| `HOTEL_QUOTES_ENABLED` | 酒店参考报价入口，默认开启；实际供应商调用仍需问道可用及必要入住条件 |
| `RESEARCH_OFFICIAL_LINKS_ENABLED` | 官网入口发现，默认开启；受搜索及页面读取预算限制 |
| `RAIL_MCP_CONFIG` | 可选铁路 Remote 的完整 JSON，默认未启用；真实 endpoint、鉴权及有效期由部署者自行提供 |
| `AI_BUDGET_TIER`、Token/金额限额 | 输出预算与模型分工独立；缺价或未知占用不按零处理 |

铁路、问道及模型兼容性均依赖实际供应商。服务测试成功不保证所有业务查询、价格和余票可得。本地向量检索继续默认关闭，无需为普通使用安装可选 embedding 依赖或下载模型。

1. 停止自己的后端实例，备份 `.env` 和数据目录；Web 默认使用 `data/web`。
2. 拉取本分支最新代码，安装 `requirements-web.txt` 并应用 `constraints-py311.txt`；新增 MCP 依赖已包含。QQ 用户按指南选择对应入口依赖。

5. 旧记录按既有兼容逻辑读取，不批量重写历史消息、报价和正式行程。已有确认仍受有效期、版本及来源保护；修改过资产的旧请求可能要求核对后重新发起。

## Windows CI 发布清单路径修复

后续云端验证显示：Ubuntu 与前端通过，Windows 完成 2001 项测试后出现三个发布清单错误。该次后端耗时约 37 分钟，退出码为 1；没有触发 40 分钟检查上限或 45 分钟作业上限。
