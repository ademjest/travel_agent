# 消息诊断入口与本地 BGE 检索升级

日期：2026-10-16。承接总体方案 O03/O05，按用户本轮确认实施。当前为代码、前端构建和隔离验收交付；正式后端未重启，本地语义检索默认保持关闭。

## 1. 日常怎样使用

更新后端并刷新网页后，在**你发出的提问下面点击“查看处理过程”**，即可查看这一条请求。无需PowerShell，也无需查找event_key。

浮层先显示中文状态和说明，下面按顺序展示接收、模型、摘要、资料检索、工具、投递记录。点击“技术详情”才显示校验码、版本等元数据。记录正在更新时可点“刷新记录”；需要分析时点“复制诊断报告”，也可展开文本手动复制。

- “未达到摘要阈值”属于正常状态，不标成故障。
- “摘要更新失败，沿用旧版”会明确提示，不会因最终任务完成而隐藏。
- 限流、权限、参数等已知错误显示对应中文；未知错误只说明记录不足，不猜测原因。
- 没有记录时说明可能尚未处理、已过保留期或来自旧版本，不能推断具体原因。
- 完成、模型返回成功或投递成功不代表回答内容准确。工具尝试次数按每条记录显示，不把HTTP层与工具层计数相加。

页面只读取已保存的元数据，不调用模型、不重跑请求，不复制聊天正文。API通过当前会话、Web任务归属和会话删除状态检查；换会话或关闭浮层会丢弃迟到响应。旧CLI仍保留，网页与CLI共用只读读取函数。

截图：[隔离界面示例](../evals/diagnostics-ui-desktop-2026-10-16.png)。画面中的旧摘要回退和限流是**人为注入的合成故障**，用于界面验收，不是正式故障记录。

## 2. embedding 接入了什么

候选为 **BAAI/bge-small-zh-v1.5**，使用 Xenova 提供的CPU ONNX量化转换，512维，模型文件约24 MB。不是此前的字符哈希实验，也不需要新部署向量数据库。

- 原模型提交：7999e1d3359715c523056ef9478215996d62a620，原模型许可证MIT。
- ONNX转换提交：75c43b069aac4d136ba6bc1122f995fedcfd2781；转换仓库未单列许可证，保留原模型出处和转换身份，不将其写成官方原始权重。
- 下载文件用固定提交和文件哈希验证。`prepare_local_embedding.py`为显式准备命令；服务运行期间不会下载模型或发送文本到外部embedding服务。
- 查询使用中文检索前缀，文档不使用该前缀。文档超过模型长度时分窗口编码后聚合，不静默只取前512 Token。此策略保证内容被编码，不证明长文本末尾事实一定被召回。
- 模型提交、编码策略和查询前缀参与命名空间，避免混用旧向量；内容变化时旧向量不参与返回，删除文档会同步删除向量。检索继续按会话范围过滤。
- 关键词与语义候选通过现有排名融合。缺少模型、依赖或推理失败时退回关键词，不自动启用已No-go的哈希检索。
- Web/OneBot启用后每30秒后台检查新增资料，每个范围每轮最多处理32个片段；不会在用户搜索时临时批量建索引。索引尚未完成时关键词检索仍可使用。

核心实现：[LocalEmbedding](../infrastructure/local_embedding.py)、[SemanticIndex](../infrastructure/semantic_index.py)。运行时装配已接通，资料检索成功或回退也能进入消息诊断。原摘要提示、模型用途配置和聊天预算没有改动；本批收费模型请求为0。

## 3. 实测结果与边界

所有实验都在临时库中使用虚构资料，使用真实本地BGE推理，不使用正式会话或收费聊天模型。新增32题先固定语料，其中开发16题、留出16题的目标主题隔离，但复用了通用干扰文档，不是严格的全体文档独立留出；仅使用开发集选择相似度门槛0.5。

| 测试范围 | 关键词 Recall@5 | 加入BGE Recall@5 | 无答案误召回 |
| --- | --- | --- | --- |
| 新开发集：11题有答案，5题无答案 | 54.5% | 100% | 两者0/5 |
| 新留出集：12题有答案，4题无答案 | 58.3% | 83.3% | 两者0/4 |
| 历史100题中的留出部分：21题有答案，4题无答案 | 83.3% | 100% | 两者0/4 |

新留出仍漏了“每星期的第一天能否参观”和过敏原交叉接触保证两个改写问题。历史语料已用于先前分析，不能当成全新独立样本；检索相关段落也不证明政策当前有效或最终回答忠实。无答案样本很少，0次误召回不代表长期误召回率为0。评测包含编码缓存，耗时不当作正式P95或纯模型速度。

证据：[新32题评测](../evals/local-embedding-pilot-2026-10-16.json)、[历史100题对照](../evals/local-embedding-legacy-100-2026-10-16.json)、[真实本地运行时验证](../evals/local-embedding-runtime-smoke-2026-10-16.json)。运行时验证包含长文多窗口、实际装配、范围隔离、源文变化排除、删除同步和检索诊断。

**当前取舍：接入和实验已完成，默认仍关闭。** 历史100题对照达到原有合成指标门槛（至少100题、平均Recall@5提高至少10个百分点、无答案误召回不增加）；这不等于正式质量准入。两份报告的production_gate_passed为null，表示未评估实际资料与回答忠实度，不另造“100条独立留出”的强制门槛。后续优先补同义改写、否定、跨条款、无答案、版本冲突，再决定是否比较BGE-M3或加入重排。

## 4. 准备与启用方式

本机模型已保存到项目 `.models/bge-small-zh-v1.5-onnx`，隔离评测依赖位于 `.local-embedding-deps`，两者都已加入Git忽略。没有改动现有Conda环境；隔离评测目录不等于已将依赖安装到正式启动环境。

以后确认启用前，在**实际启动服务的Python环境**安装 `requirements-embedding.txt`。首次换机器时再运行准备脚本：

```powershell
python -m pip install -r requirements-embedding.txt
python scripts/prepare_local_embedding.py
```

然后在网页“服务配置 → 预算与记忆”填写模型目录 `.models/bge-small-zh-v1.5-onnx`、门槛 `0.5`，启用“本地混合检索”，保存后重启后端。CPU本地推理没有远程模型Token账单，但有本机内存和计算开销。当前验收未达正式准入，因此本批未替用户保存开启配置、未更新正式库索引。
