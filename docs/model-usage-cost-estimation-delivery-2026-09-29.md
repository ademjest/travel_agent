# 模型 Token 费用估算修复交付

日期：2026-09-29  
状态：已实施并验证

## 完成内容

- 默认费率币种由 CNY 改为 USD，设置页、运行时、示例配置和文档保持一致。
- 历史 `estimated_cost=NULL` 记录在读取报表时按当前生效费率动态回算，不修改历史数据库。
- 旧记录缺少缓存 token 拆分时，缓存量按 0 处理，即全部输入按普通输入费率保守估算。
- 真正缺少输入/输出 usage 和当前费率不完整分别统计，不再混为同一种“未知”。
- 已经保存费用的记录继续使用原费用，不因用户后来修改费率而重新计价。
- 新模型调用保存输入、缓存输入、输出费率快照、币种、配置版本、费用来源和估算版本。
- 旧费用记录没有币种时，报表按当前币种展示并明确标记为币种推定。
- 多币种费用使用 `cost_breakdown` 分币种返回，不错误合并成一个金额。
- 前端显示已知费用小计、按当前费率回算次数、缓存拆分缺失次数和真正无法估算次数。
- 前端不再用“部分未知”覆盖整个费用单元格。
- 费用区域增加待重启提示，说明报表仍在使用当前运行进程中的旧费率。

## 使用说明

修改费率后仍需重启 `run_web.py`，因为模型调用和历史回算都使用当前运行进程中的生效费率。重启并刷新设置页面后，历史费用会自动按新费率显示，无需删除聊天或数据库。

报表中的历史回算是本地参考值：

- 缓存拆分缺失的旧记录按普通输入费率保守估算；
- 历史币种缺失时按当前币种展示；
- 不等同于供应商最终账单；
- 如果以后切换币种，已保存快照的调用和回算调用会分币种展示。

## 建议人工测试

1. 启动 Web，打开服务配置，确认默认币种为 USD。
2. 配置输入、缓存输入和输出费率，保存后确认费用区域出现待重启提示。
3. 关闭并重新运行 `run_web.py`，刷新页面。
4. 确认原“部分未知”已改为具体费用，并显示历史回算次数。
5. 发起一次新对话，再刷新设置页；确认新调用增加费用，且不增加历史回算次数。
6. 临时清除输出费率并重启，确认报表保留已经持久化的历史费用，同时将未计费记录标成“费率不完整”。
7. 测试完成后关闭 `run_web.py`，确认 8080 端口释放。
