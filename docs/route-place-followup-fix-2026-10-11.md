# 地点查找与多轮纠正修复总结

日期：2026-10-11。基于10月11日用户提供的五轮路线查询截图。本轮使用用户授权的真实高德 API 验证，未调用付费模型、修改正式数据库、修改密钥或重启正在运行的服务。

## 实测原因

1. `/v3/place/text` 的连写、空格及连字符查询没有提供目标校门，返回了学校、院系、公交站和周边商户；地理编码还会把南大门降为学校中心。
2. `/v3/assistant/inputtips` 返回了校门的独立 POI ID、行政区、坐标及通行设施类型。相同 ID 在本次 `/v3/place/detail` 测试中没有返回详情，因此不能把详情接口作为唯一校门来源。
3. 终点简称“航天信息产业研发中心”实际返回“航天三院信息产业研发中心”。旧完整名称规则拒绝后没有展示候选，用户只看到笼统的“未找到”。这不证明两个名字可无条件互换。
4. 本次高德 `extensions=base` 响应缺少 `adcode`，却被旧程序拿来校验区县，导致正确结果被拒绝；`extensions=all` 提供了该字段。
5. 代码还存在连字符未规范化、剥离“武汉”后残留“的”、逗号后的门牌地址丢失，以及补充终点时旧原句覆盖最新起点的问题。

## 已实施的改动

- 名称规范化兼容连字符、括号及行政前缀连接词，保留原始查询用于显示和回执。
- 校门先验证父机构的唯一城市，普通 POI 查询失败后在该城市调用输入提示。提示必须有 POI ID、有效坐标、可解析的城市/行政区和 `991400` 通行设施类型。
- 校门匹配只接受入口名称及父机构的对应关系，可识别机构名称中的东/西/南/北校区修饰；不接受学院门冒充大学门，也不接受商户地址里提到校门的结果。
- 路线 POI 查询请求完整字段；区县约束仍严格核对区县编码，城市编码不再被错误地要求等于其下辖区县编码。
- 名称相近但不同的机构仅展示候选，请用户明确确认完整名称，不自动计算路线。
- 明确纠正中的“具体是……路1037号”保留在端点原文中，解析时将名称和补充地址分开，分别检索和核验。不把校门回退为门牌号或学校中心。
- 路线接续使用当前槽位，而非带旧起点的初始请求。单工具与组合查询共用保护：模型不能用本轮未提及的旧端点覆盖当前端点；用户明确更正仍然生效。
- 日志记录检索阶段、查询词、候选数、排除原因和接受的 POI ID，不记录 API 密钥。回复区分没有可用候选与返回结果未通过校验。
- 解析版本更新为 `route-poi-v3`，既有路线检查点按新版本隔离，不复用旧版结果。

## 手动验收

先停止旧 Web 后端，再沿用现有方式启动（例如 `start-web.cmd`）。仅刷新网页不会加载新的 Python 代码，不要同时启动两份服务。无需清空聊天或数据库；为排除过期任务与旧消息干扰，首次验收建议新建聊天。

### 直接路线

发送：

> 从华中科技大学启明门到武汉市东西湖区航天三院信息产业研发中心，驾车怎么走？

应显示华中科技大学东校区启明门和滨河北路9号研发中心，并提供武汉范围内的路线。不能出现佛山同名门、学校中心替代门或约1000公里路线。

### 连续纠正

在同一新窗口依次发送：

1. 我想从华中科技大学启明门去武汉东西湖区的航天信息产业研发中心，驾车路线应该怎么走？
2. 那起点改成华中科技大学的南大门
3. 终点改为武汉的航天信息产业研发中心
4. 是航天三院信息产业研发中心
5. 起点是华中科技大学-南大门，具体是武汉市洪山区珞喻路1037号

前三步应保留当前起点，并展示完整终点候选请你确认。第四步不能恢复“启明门”，第五步要保留1037号并使用南大门坐标。也可用更明确的“终点是航天三院信息产业研发中心”完成确认。
