# 普通规划、联网研究与行程草稿上下文联通交付

日期：2026-09-22

依据：[问题分析与方案](conversation-plan-research-context-analysis-2026-09-22.md)。P0 与 P1 已在本地实施，尚未提交 GitHub。

## 已实现

- 自然语言“了解网上攻略、参考小红书”等表述可直接进入 ResearchService；固定关键词是快速路径，Intent IR 同时增加 `research/search_travel_guides` 作为语义入口。
- `travel-research` skill 的目的地、平台偏好和严格来源设置经过服务端校验。当前会话保存研究来源偏好；同一目的地的相关搜索继承，其他会话和目的地不继承。
- 新增持久化 `planning_artifacts`，区分 `exploratory` 与 `research_backed`。普通 Agent 的多日规划回复、研究报告都会保存为方案；旧聊天在首次读取时按来源事件懒加载，不依赖最近对话字符预算。
- Intent IR 增加 `trip/create_from_plan_artifact`。模型引用服务端方案序号，不能生成资源 ID；“最开始／刚才搜索”由服务端绑定具体草稿。
- 多个天数方案只询问天数，并持久保留酒店等本轮变化。选择后重新查询地点与酒店，生成日期待定的行程创建预览；确认前不插入 `trips`。
- 确认时校验方案版本、任务版本和行程状态，成功后插入正式行程并将方案标记为 adopted。删除或变化的方案不能用旧预览确认。
- 兼容旧会话：当前开封会话在临时副本中可索引为方案 1（探索型，2／3 天）和方案 2（研究型，4 天），顺序稳定。
- Web 右栏增加“方案”标签，展示方案类型、序号、天数和摘要，可填入采用命令或软删除。会话删除会同时清理方案和会话级研究来源偏好，删除摘要显示方案数量。
- 增加“查看方案草稿”“删除方案草稿 P-编号”命令。

## 原三轮预期行为

1. “想了解攻略参考，最好参考网上攻略比如小红书”进入联网研究，并保存小红书为会话来源偏好。
2. “帮我搜索开封四日游攻略”继承来源偏好，产生独立的四日研究方案，不覆盖最开始方案。
3. “按照最开始的规划安排，加酒店推荐”定位方案 1。由于包含 2 天与 3 天两套，只追问选择哪套；选择后生成带酒店候选的创建预览，确认后保存。
