## 2. 多需求分流的实际边界

规则为纯解析函数，不执行操作。第一版支持窄范围完整句式，例如：

- `武汉现在天气怎么样？`
- `查询天气武汉；查询天气长沙`
- `查询天气武汉；查询路线武汉站→湖北省博物馆`
- `从武汉站到湖北省博物馆开车怎么走？`
- `酒店预算改为320元/间/晚`
- `酒店预算改为320元/间/晚；不要夜游`

句子只被部分覆盖、有不支持的条件/否定/更正、或者混合读写时，不先执行命中的子项。完整原文进入模型；对于可识别的复合边界，如果模型仅返回一部分，至多补一次完整性解析，仍不完整则说明本次未执行。规则本身不保证理解任意自然语言。

下游区分单业务、独立只读组合、同一行程更新以及已有行程/关联提醒联动。未支持的跨业务组合会保留识别出的事项并澄清，不用第一项成功冒充全部成功。复杂比较、条件任务、同义自由表达仍可能使用原模型路径。

复合规则查询按操作实例保存快照与结果，重复投递或处理中断不会重新调用已完成的子项。规则版本不兼容时明确要求重新发起，不用新语法静默重解释旧请求。单项读取继续复用原有工具重试、物理次数和检查点。

新开关：`AI_RULE_ROUTING=false` 可停用新增规则直达；`AI_LOCAL_PLANNING=false` 可停用局部生成。默认均开启于新版代码。停用开关不撤销本次修复的完整请求检查和确认保护，也不能代替版本回退。

## 3. 当前事实、草稿和局部修改

### 当前状态

字段值仍来自已保存行程和待确认草稿，来源元数据放在已有 spec 内。当前重点覆盖预算/单位、住宿与餐饮偏好、交通、节奏、夜游，以及指定日期/时段要求；没有自动结构化所有自由对话。

已保存420元/间/晚、草稿350元/间/晚会分别展示。未知、否定和明确清除不混为一谈。旧数据缺少来源时显示“历史来源未完整记录”，不伪造引用。

当前旅行状态在相关问答中进入现有上下文预算。只在目标明确时提供；多行程先消歧。未能完整纳入的字段会列为未提供，不能依据旧摘要补猜。历史自由文本不当作当前字段真值注入。

### 局部更新

住宿/餐饮更新只检索相关类别并使用已有确定性推荐逻辑。没有新查询依据时不把过期候选重新当作新成功结果。预算仍然是用户目标；没有实时房价就不会宣称酒店已符合价格要求。

指定日期或时段修改只接受活动列表，锁定范围之外的活动由服务端保留，再检查完整行程的天数、活动数量、必去地点、重复地点和室内外约束。局部失败不能偷偷扩大修改范围。

“先改预算，再改第二天下午”会继承现有有效草稿；两项变更进入同一累计预览。指定日期修改现在先预览、后确认，相关原有测试已更新为验证这条完整流程。过时路线不能仅因活动未变就无限复用；原路线复用分支要求有效且五分钟内的带时区时间戳。

### 界面与确认

需求卡显示已保存值和草稿差异，可查看来源。当前提供住宿预算及不夜游的结构化编辑入口；其他复杂修改仍可用聊天输入。

差异由服务端比较生成，包括字段变化、具体日期活动前后、酒店候选和路线变化状态；确认绑定实际草稿版本。默认比较“已保存版本→完整当前草稿”，不会只展示最后一句造成遗漏。仍能展开完整预览核对关联提醒。

字段编辑经 Inbox 接收，执行时再次检查归属、行程版本和草稿身份；重复请求同结果、同ID不同内容冲突。观察/预览模式不写入草稿。

## 5. 真实模型效果

模型固定为 **gpt-5.6-sol**；SDK/传输隐式重试关闭。使用隔离数据库和合成旅行资料，地图/天气是固定测试数据，摘要在对照任务中关闭。测试用于比较模型与业务路径，不等同于真实地图、搜索或生产完整旅行验收。

| 场景 | 原路径 Token | 优化路径 Token | 结果 |
| --- | --- | --- | --- |
| 明确天气查询，第1/2轮 | 3912 / 3912 | 0 / 0 | 数据查询检查通过，规则省去意图模型 |
| 酒店预算调整，第2轮 | 5372，2次模型请求 | 0，0次模型请求 | 均生成草稿并在确认后保存；活动保持 |
| 指定日期改室内，第1轮 | 1424 | 710 | 两者通过本轮约束与确认检查 |
| 指定日期改室内，第2轮 | 1446 | 681 | 两者通过本轮约束与确认检查 |
| 已保存/待确认预算问答 | — | 489，1次模型请求 | 正确回答已保存420、待确认350，单位元/间/晚 |
| 武汉和长沙天气组合 | — | 0 | 两项工具查询均执行，没有按领域合并遗漏 |
| 天气与取消提醒混合 | — | 4174（第2轮） | 保留全部事项并澄清，无部分执行或擅自取消 |

指定日期的两个配对样本都减少了约一半 Token，但样本量很小，不能推广为整个项目长期节省比例。表中的0表示该隔离路径未发出模型请求，不表示实际生产中后台摘要、外部API和所有相关任务都零成本。

首轮预算基线最初被测试判失败，原因是模型将“320元/间/晚”整体放入数值字段，测试只接受纯“320”。单独核对持久化版本后确认数值/单位等价且活动未变；[原始结果](../evals/state-routing-live-2026-10-18.json)保留，[离线复核](../evals/state-routing-baseline-budget-review-2026-10-18.json)独立保存，不冒充新生成。第二轮修正等价判定后重新实测通过，并修正了界面重复拼接单位的显示。

第二轮9项场景检查通过。其中部分优化分支不调用模型；实际请求数与场景数分别计量。

每轮实测均保留独立源码快照，运行时源码未改变。其后的恢复快照保护、观察模式隔离、普通叙述分流收紧和局部输出确认标识由离线回归验证；未将这些后续修改描述为又做过一轮真实模型测试。
