## 1. 建议审核结论

建议采用“结构化状态优先、上下文按用途装配、摘要按需生成、向量检索按效果启用”的路线。保留工具 Agent、语义编译器和专用规划器，减少它们之间的重复理解和重复输入。

优化目标是降低**每个成功业务任务的总费用**，同时维持时间解析、权限、确认、来源和任务恢复的正确性。不以减少模型调用次数或提示词长度作为唯一成功标准。

建议本次批准阶段 0—2 的实施方向，以及阶段 4 的配置和验收要求；阶段 3 先作为可选检索实验，通过效果与成本门槛后再决定是否启用。批准本文档不表示立即切换正式模型、批量处理历史资料、发布 GitHub 或执行无上限的真实接口评测。

| 审核事项 | 推荐选择 | 影响 |
| --- | --- | --- |
| 开源默认档位 | 均衡模式；提供明确的经济模式 | 兼顾现有体验和预算，所有档位仍受硬上限约束 |
| 原有模型配置 | 保留单模型配置即可运行；用途级模型覆盖可选 | 不强制用户注册多个供应商或填写多个 Key |
| 长期记忆 | 沿用结构化偏好和业务状态，增加按需会话摘要 | 不对所有聊天自动建立跨会话画像 |
| 向量库 | 默认关闭；优先评估本地嵌入式索引 | 不把独立数据库服务、模型下载作为基础安装要求 |
| 跨会话范围 | Web 仅共享已保存偏好；其他资料按现有会话范围 | QQ 继续按平台、群、本人隔离；QQ 与 Web 不自动互通 |
| 金额预算 | 用户配置真实费率后可执行；未知费率明确标记 | 不用模型名称猜测第三方账单，不把未知用量算作零 |
| 实施方式 | 分阶段、小范围验证、各阶段可退回旧路径 | 不同时重写全部 Agent、存储与业务服务 |

### 2.2 已有数值只能作为历史样本

讨论期间只读统计了两个默认数据库中保留的模型用量：

| 数据库 | 调用过模型的事件 | 网关调用 | 输入 token | 输出 token | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| QQ | 17 | 34 | 63,573 | 8,418 | 71,991 |
| Web | 6 | 11 | 9,348 | 2,678 | 12,026 |
| 合计 | 23 | 45 | 72,921 | 11,096 | 84,017 |

输入 token 占比约 86.8%，但不能据此推断费用占比。QQ 记录来自 9 月 12—14 日，Web 记录来自 9 月 18 日，记录的模型标识为 `gpt-5.5`。零模型请求不在此表内，删除与留存策略可能影响记录完整性；这些数据不是最新版本、全部用户或供应商账单的完整统计。

此前假模型整链路模拟：固定命令“查询天气 西宁”为 0 次调用；同义自然语言为“语义编译 + Agent 工具选择 + Agent 回答”共 3 次；“你好”为 2 次。它验证调用结构，不衡量真实模型的成功率或计费。

当时固定编译提示词为 3023 字符，以 `o200k_base` 估算约 1164 token。此估算不包括完整请求协议开销，不能替代实际供应商 usage；提示词变化后必须重新测量。

### 2.3 已确认的改进点

1. 大量自然语言先进入语义编译，但不支持的操作结果被丢弃，后续模型再次解析。
2. `ContextBuilder` 通常读取多类材料后截断；无相关片段时仍可能补充低相关最新文档和摘要列表。
3. 多个组件使用独立上下文；只改 `ContextBuilder` 无法覆盖规划、语义解析、研究和图片调用。
4. 行程请求传递完整 `spec`、地点候选及旧行程；`source_context` 等可重复进入模型。
5. 各用途默认使用同一个模型，未单独限制时输出上限为 8192。
6. 群聊/Web 文档路径已先去重再摘要；私聊 `prepare_attachments()` 仍可能在最终去重前生成摘要。
7. 普通图片主要复用同事件结果；不同事件重复上传相同图片仍可能重新识别。
8. 部分预约写操作在成功后继续请求模型回答，最后又用确定性回执替换其内容。
9. `scripts/evaluate_tasks.py` 的运行时装配没有完整启用生产语义编译路径，不宜直接作为新版成本基线。
10. `.env.example` 中 `shadow` 与运行时代码缺省 `execute` 不一致；shadow 仍消耗模型额度。

## 3. 范围与不变量

本方案包括：提示词优化、用途级上下文、重复解析消除、会话摘要、检索实验、用途级模型与输出预算、缓存、成本计量和评测、最小预算设置界面。

本方案不包含：多账号登录、QQ/Web 身份绑定、自动训练私人模型、自动生成或执行 skill、向量化所有历史聊天、自动订票支付、新建通用多 Agent 框架、微服务拆分或发布部署。

实施过程中必须保持：

- 当前用户要求和已确认任务约束优先于长期偏好；偏好与资料不能授权业务修改。
- 提醒时间、资源版本、身份、待确认操作等从结构化存储读取，不依赖向量相似度或生成式摘要决定。
- 原文依据、否定条件、时间歧义、业务确认、版本冲突和租约校验不能为节省 token 而删去。
- 上下文不足时保留必要追问；不截断重要字段后假装理解完整。
- 模型返回的成功声明不能替代实际业务回执；已提交业务不得因预算耗尽被误报为全部失败。
- 任何长期派生物都必须有来源与失效机制；删除后不能由旧任务、摘要或历史检索自动恢复。

## 4. 目标设计

### 4.1 五层信息，按需读取

| 层次 | 内容 | 主要存储/读取 | 进入模型的原则 |
| --- | --- | --- | --- |
| 当前工作状态 | 任务字段、缺项、当前对象、版本、用户补充 | 现有 Task/Trip/Reminder Repository 精确读取 | 必要字段优先，不发送完整数据库对象 |
| 长期偏好 | 节奏、交通、兴趣、预算、回复风格等 | 现有 PreferenceRepository | 仅相关字段；停用/删除状态同样有效 |
| 会话摘要 | 已讨论结论、未决问题、重要纠正及引用 | 新增小型会话摘要存储 | 当前会话、按需；不覆盖业务真实状态 |
| 资料证据 | 文档、图片事实、研究来源 | 现有存储与 FTS；可选向量索引 | 相关片段、有效版本、来源与获取时间 |
| 原始归档 | 原始对话、原文、原图、历史版本 | 沿用现有留存和删除规则 | 默认不注入；明确需要时回查 |

“会话摘要”是对当前会话历史的派生压缩，不新增跨会话分享规则。Web 已保存偏好仍可跨本地会话应用；文件、图片、具体行程和研究结果不因此跨会话检索。

### 4.2 请求用途决定上下文

组件共享范围过滤、片段选择和预算规则，保留各自的输入格式；不向所有模型发送同一份上下文。

| 用途示例 | 必要信息 | 默认不提供 |
| --- | --- | --- |
| `intent_parse` | 当前输入、匹配的待补任务、必要时间参照 | 大段群聊、全文文档、全部业务对象 |
| `reminder_continue` | 对应任务、已有日期/时段、缺项、上次问题 | 无关资料和其他用户任务 |
| `travel_lookup` | 明确查询参数、必要引用或地点接续 | 长期行程、兴趣、全部文档概要 |
| `document_qa` | 问题、相关原文、来源/版本，必要的短历史 | 所有文档的固定概要列表 |
| `trip_plan` | 已提取约束、实际采用偏好、精简 POI | 原始聊天长文和无关 POI 字段 |
| `trip_edit` | 修改意图、受影响部分、边界约束、当前版本 | 无关的旧讨论与完整来源正文 |
| `research_synthesis` | 已筛选证据、问题、来源及可靠性状态 | 每个网页的整段重复正文 |

用途由当前执行阶段或已有分派结果确定；不另加一次模型调用专门挑选上下文。

装配顺序：确认读取范围 → 精确取当前状态 → 选相关偏好/摘要/证据 → 去重 → 按完整片段装配 → 对最终模型请求计量。必要信息放不下时，缩小任务或明确追问，不通过静默截断解决。

token 计量应覆盖系统提示词、工具定义、当前输入、记忆、工具结果及模型能力允许的输出预留。已知 tokenizer 用匹配的编码；未知兼容模型标注“估算”，沿用保守边界，不冒充准确 token。每次 Agent 循环都重新检查，不能只限制第一轮。

### 4.3 三种模型角色保留，减少重复理解

- 固定命令、明确按钮和符合严格格式的当前任务回答优先确定性执行。
- 自然语言形成可复用的结构化结果；提醒直接调用已有 `handle_intent()`；增加受限的简单只读查询执行路径，复用城市、起终点等已经验证的字段。
- 新建行程复用需求提取结果，避免先运行一个结果无用的完整编译器，再重复提取同一需求。
- 一条消息包含多个动作、多个对象或否定条件时，保留完整语义判断和既有校验，不为命中快速路径丢失其他意图。
- 简单查询直接渲染有时间和局限说明的结果；需要比较、解释、综合建议时才再调用模型。
- 预约操作的所有必要动作/对象均有成功回执且没有未处理问题时，直接返回回执，省去随后会被丢弃的模型回答。
- 不以关闭语义层作为经济模式的主要手段；“10点吧 → 上午”和没有固定关键词的合理请求仍需可用。

输出与执行是两个步骤：模型提出的结构化结果先接受 schema、原文、范围、状态和动作一致性校验，再执行，复用解析结果不能绕过这些检查。

## 5. 阶段 0：冻结基线并补齐计量

目标：在改变行为前，知道费用花在哪里，并能重复比较。

实施项：

1. 为基线记录源码清单/哈希、配置摘要、模型与提示词版本、测试集版本；不把当前整个脏工作区自动提交或回退。
2. 评测通过生产 `build_runtime()` 装配，并在边界注入模型、数据源和投递替身；不能用空模型配置装配后漏掉语义/研究组件。
3. 在网关增加 `purpose`、业务任务/运行关联、模型、provider 配置别名、配置版本、输入估算、输出上限、耗时和结果状态。
4. 记录实际输入/输出；供应商返回时记录缓存读写、推理用量等细分。推理 token 若已包含在输出总量中，不重复相加。
5. SDK 重试、调用超时及未返回 usage 明确标记为费用可能不完整；网关调用次数与物理 HTTP 尝试次数分别说明。
6. 聚合所有成本：解析、生成、修复、摘要、embedding、重排，以及可获知的搜索调用。第三方非 token 费用独立列示。
7. 成本统计默认不记录正文、完整提示词、密钥或用户资料；诊断仅记录各部分长度、选择原因和片段数量。开发样本需要正文时使用合成数据。

网关费用估算使用供应商真实费率配置，记录币种和费率版本；未知价格展示 token 与“费用未知”。输入总量中的缓存部分应按实际计价规则拆分，不能先按原价算一遍再重复加缓存费。

新增不含正文和事件引用的本地费用累计计数，与可删除的调用明细分开设计。会话删除清理明细、来源和可检索派生物；日/月累计用途及留存必须在设置中说明。普通删除会话不应无意重置日额度。当前身份范围沿用现有本地使用者/QQ 范围，不借预算功能新建跨平台身份关系。

验收：完整运行时的调用数量与模拟记录一致；能区分语义、规划、摘要、视觉、研究和修复；未知 usage 不显示为确定的零消费；导出不含用户正文或凭据。

## 6. 阶段 1：结构化精简、提示词与调用链优化

这是首要实施阶段，先取得不依赖向量库的收益。

### 6.1 上下文与提示词

- 继续使用现有 `ContextBuilder`，增加用途和预算参数；先抽出小型上下文策略，不新建通用记忆框架。
- 任务 slots 按用途挑选字段，避免把 `candidate_trip`、长资料和嵌套对象作为任务概要全部序列化后截断。
- 引用消息、群消息、近期对话按消息标识或内容来源去重。
- 独立天气等请求不检索或注入低相关文档；资料问答无匹配时返回空或追问，不自动填满最新文档。
- 系统提示词保留职责、事实/权限边界和精简协议；提醒、规划、查询示例按用途加载。稳定规则在前，时间与本轮动态信息在后。
- 偏好缺失/停用/删除时，不能借历史聊天或摘要重新套用旧偏好；当前已实现的遗忘保护继续保留。
- 输出采用紧凑 JSON 和模板；不为了缩短字段名破坏可读性或来源校验。

### 6.2 行程和资料

- 给规划器发送显式字段白名单：需求与有效约束、来源引用、必要 POI；电话、抓取元数据等保存在服务端。
- POI 先保留必去和约束必需候选，再按天数、分类、地理位置裁剪；不以固定过小 top-k 导致必去点遗漏。
- 已提取的日期、偏好和任务字段复用；`source_context` 仅在确需再次解释资料时进入请求。
- 单日重排产生局部候选，由程序合并并验证完整行程约束；跨日冲突仍允许读取必要邻接信息，不盲目只给一天。
- 保留已有日期平移、删除、移动等确定性修改分支。
- 群聊/Web 文档摘要去重维持现状；私聊准备路径在范围校验后复用已有摘要，避免同文档重复生成。经济模式提供按需摘要。
- 普通图片逐步分离“事实提取”和“按问题回答”，事实缓存绑定图片哈希、读取范围、模型和提取版本；不直接复用不同问题的旧答案。
- 图片缩放/裁剪作为独立开关，使用小字、日期、票据样本验证；文件压缩率不作为视觉 token 节省证据。

### 6.3 第一批可验证的调用目标

| 案例条件 | 优化目标，非已测成果 |
| --- | --- |
| 完整固定天气命令 | 继续为 0 次 LLM |
| 单意图、单地点、无歧义自然语言天气查询 | 经济模式一次结构化解析后模板输出，目标 1 次 |
| 明确按钮填入待补时段 | 程序校验并接续，目标 0 次；模糊口语保留模型 |
| 普通闲聊 | 避免无效编译前置，目标 1 次 |
| 条件完整的新建城市行程 | 目标 需求提取 + 规划 2 次；一次修复单独计量 |
| 全部请求操作成功、无额外问题的预约写回执 | 成功后不再调用模型润色 |
| 到期提醒、已创建的定时查询和规则监测执行 | 不额外引入模型决策 |

复杂复合请求不承诺一次调用。若统一语义路由需要较多改造，先处理有明确边界的简单查询与回执，逐领域迁移；旧路径只作为有记录的回退，不双跑生产请求做影子对比。

验收：零模型路径保持；口语接续、跨主题切换、否定和多对象案例不退化；所有被裁剪内容都有分类统计；业务验证与并发恢复测试通过。

## 7. 阶段 2：按需会话摘要

### 7.1 写入和使用策略

- 摘要仅服务当前会话和允许读取的成员范围；不从群聊生成跨成员私人记忆。
- 优先使用结构化任务或业务快照；它们已经表达的事实不再用 LLM 摘要一次。
- 默认没有达到条件就不生成。初始实验阈值：新增历史超过 2500 估算 token、距上次摘要至少 8 条新消息，并且后续请求确需引用旧对话；阈值可通过评测调整。
- 输入为旧摘要与新增消息，输出包含相关结论、未决问题、重要否定/纠正和来源引用。避免把助手猜测写成用户事实。
- 保留最近 1—2 轮必要原文，精确日期、金额、业务 ID 与确认状态从数据库回查。
- 生成后校验来源、版本和长度，成功才替换；失败继续使用受预算约束的原有选择策略。
- 摘要更新独立计费并归属原会话/任务预算；每个用户请求最多触发一次摘要生成，不无限递归压缩。可恢复任务复用已成功摘要。
- 摘要默认按需生成，不因服务器空闲而后台扫描全部历史。短会话和一次性请求通常无需摘要。

### 7.2 最小数据设计

会话摘要至少包含 `platform`、`scope_id`、`owner_id`、摘要版本、覆盖的消息边界、来源引用、所依赖偏好/业务版本、更新时间和状态。源内容哈希、提示词版本及模型标识用于识别需要重建的派生数据。

摘要不是业务真实来源。当前业务记录和本轮明确修正优先于摘要；发现矛盾时回查，不继续把错误旧摘要作为新增摘要依据。

会话删除使摘要立即不可检索并清理存储；删除相关来源或忘记偏好时，按依赖关系使摘要失效。发布新摘要前重新检查会话/来源代次，阻止删除后的迟到结果写回。无法精确定位受影响条目时，宁可失效整份摘要。

### 7.3 验收门槛

在长会话专用样本上，把摘要创建、更新、后续输入、重试费用全部计入同一会话；净费用中位数目标降低至少 15%，且不能提高关键事实错误。此数值是发布目标，不是收益承诺。短会话不得因主动摘要增加调用。

未达到门槛时保持摘要默认关闭，交付失败分析而不继续堆叠更多摘要模型。

## 8. 阶段 3：可选向量与混合检索实验

启动条件：阶段 1 的 FTS/结构化读取仍在同义表达、跨片段资料定位上存在明确漏检，且有固定样本可复现。

### 8.1 方案

- 向量只索引非结构化资料证据，第一批限定已授权的文档片段、图片事实和研究片段；不自动索引全部聊天和用户身份资料。
- 默认安装继续只依赖现有 SQLite/FTS；可选本地嵌入式方案优先评估 `sqlite-vec`，验证 Python 3.11、Windows/Linux 的安装、许可证和发行可用性后再确定。暂不要求用户部署 Qdrant 等独立服务。
- embedding 模型由用户选择本地或供应商服务。本地模型需说明体积、许可证、CPU/RAM 和下载要求；远程 embedding 明确资料发送范围及费用。
- 一份内容按哈希、embedding 模型/维度/版本建索引；源内容未变时复用。不因重启重算。
- 在允许读取范围内分别执行 FTS 和向量召回；合并去重采用排名融合，避免直接混加不可比较的原始分数。
- 初始上限每路候选 10 条、合并候选最多 20 条，再按相关性/有效性与 token 预算选 2—4 个片段；允许返回 0 条。这些数量需通过评测调整。
- 初版不新增 LLM query rewriting 或 LLM reranker。只有证明收益覆盖额外成本时才单独提出。
- 时效事实继续使用真实数据源。天气、票量、旧预约规则不能因语义相似而变成最新事实；沿用研究和规则既有有效期、版本及冲突保护。

### 8.2 一致性与删除

SQLite 保存权威来源与版本，索引是可重建的派生物。索引项记录来源、范围、版本和失效代次；读取时再次验证源记录存在且有效。

删除源、删除会话或变更权限后立即阻断查询，再清理向量与缓存；索引滞后、模型切换、重建失败均可退回 FTS。模型变更用新索引命名空间，不混用不同向量维度。

### 8.3 Go / No-go

在留出的语义检索样本上，对照阶段 1/2 版本，候选目标为 Recall@5 提升至少 10 个百分点；最终进入模型的证据 token 不超过同用途预算，端到端答案来源正确率不下降，任何跨范围召回和删除后复现均为阻断项。

费用必须包含初始索引、增量索引、查询 embedding 与下游生成。只有在明确使用量假设下优于 FTS 的方案才建议启用；未达到收益时保留为实验或不引入。

## 9. 阶段 4：预算档位与开源交付

本阶段的计量和配置基础在阶段 0/1 建立；最终根据各阶段评测收敛为用户可理解的设置。

### 9.1 档位

| 项目 | 经济 | 均衡（建议新安装默认） | 高质量 |
| --- | --- | --- | --- |
| 解析模型 | 用户指定的便宜且通过评测的模型；未指定沿用默认模型 | 同左，允许预算内升级一次 | 可使用默认强模型 |
| 简单查询 | 模板，复杂解释按需 | 按需解释 | 更充分分析，仍不重复确认已有事实 |
| 上下文 | 最小相关状态/证据 | 相关历史与资料 | 较充分但仍受完整请求上限约束 |
| 文档摘要 | 按需 | 新文档可生成并复用 | 按资料需要提高输出预算 |
| 会话摘要 | 阶段 2 验收后按需启用 | 同左 | 同左，不每轮生成 |
| 向量检索 | 默认关闭 | 实验通过且用户启用才使用 | 同左，不自动启用付费 embedding |
| 规划修复 | 必要时最多一次，计入任务额度 | 最多一次 | 首版仍最多一次；提高上限另行评测 |

档位不承诺固定模型价格，不自动修改原用户的模型 ID 或 Key。升级已有安装先保留原行为，提供档位选择；新安装配置、示例文件和运行时缺省必须一致。

### 9.2 初始用途预算

下表是均衡模式的**待评测初值**。记忆预算只指注入的状态、偏好、历史和证据，不含当前消息、系统提示词和工具定义；网关仍对完整请求单独校验。预算是上限，不要求填满。

| 用途 | 记忆/证据上限，估算 token | 输出上限初值 |
| --- | ---: | ---: |
| 意图解析/提醒接续 | 800 | 1024 |
| 简单旅行查询 | 600 | 768 |
| 文档问答 | 2200 | 1536 |
| 新建行程 | 3000，POI 单独计入完整输入 | 4096，随 1—14 天天数评测 |
| 局部行程修改 | 1800，必要边界状态不静默删除 | 2048 |
| 会话摘要生成 | 旧摘要和新消息合计单独限制 | 1024 |
| 研究综合/图像提取 | 按来源数/图像能力单独限制 | 2048—4096；长结构另设受控上限 |

推理模型的隐藏推理可能占用输出额度；不支持某参数的兼容服务不得盲传。输出不足时先识别截断原因，在总预算内至多一次受控调整，不连续生成同一不完整 JSON。

完整请求、事件和多轮业务任务都设置上限，避免每条补充消息重新获得无限额度。跨请求摘要任务继承预算归属；后台补发不触发生成。用户设置日/月金额上限时，按同一预算范围原子预留，实际返回后结算；未知 usage 保留保守预留并标记，不能直接释放成零费用。

没有费率时使用调用/token 限额，明确不能保证金额上限；用户要求强制金额控制但价格未知时，要求补齐费率或选择已知配置后才发起模型调用。首版费用配额属于应用级尽力控制，仍建议用户在供应商侧设置账单限额，尤其兼容接口超时和内部重试的账单可能无法完全获知。

### 9.3 配置与可观测性

- 最小用户设置：预算档位、用途级可选模型、日/月限额、摘要/向量开关、实际费率；高级 token 数值放折叠区。
- 继续使用既有配置白名单与重启生效约定；设置页区分“已保存”和“正在使用”。不得绕过现有密钥/端点绑定、只写不回显和防误提交机制。
- 第一版用途级模型覆盖共用已配置供应商端点；跨供应商路由不是前置要求，后续需要时再扩展凭据结构。
- 展示最近请求的调用次数、用途、输入/输出、可获知费用和未知部分；不显示提示词或用户私密资料。
- `shadow` 清楚标为消耗额度的诊断模式，默认不做生产双跑；独立 `legacy` 回退开关表达禁用新版编排，不能复用 shadow 名称。

## 10. 验收与对照实验

### 10.1 样本与运行方式

先整理 100 个固定、可复现的合成业务案例，按完整多轮任务统计：简单/固定查询 15、提醒接续 20、行程 20、文档 15、图片 10、研究 10、范围与遗忘 10。可以复用既有测试素材，不把正在使用的私人会话直接上传作评测。

另设长会话摘要与同义资料检索留出集，不用同一组样本同时调参与报告改进。关键模型案例可重复运行 3 次记录波动；真实接口评测须先给出次数、费率和总费用上限，再在获准额度内执行。本方案编写不启动这些调用。

离线用同一运行时验证调用链和确定性结果；真实模型验证语义质量与实际 usage。高德/搜索对照优先使用相同证据快照，避免外部数据变化使对比失真；真实数据新鲜度另测。

### 10.2 必测情形

- “明天提醒我买票 → 十点吧 → 上午”、无固定关键词的提醒、否定要求、换话题、多待补任务及引用接续。
- 同日消息修改任务版本、旧预览确认、删除后的迟到摘要/索引写入、模型调用期间取消。
- 删除/停用偏好后旧历史仍存在，模型不得恢复应用；“本次不用偏好”不改全局值。
- 文件同名不同版本、同图不同问题、图中小字与否定规则、文档中伪装授权、过期研究和冲突来源。
- 单地点查询不读取无关文档；局部行程修改不改其他日期，不遗漏必去点与跨日约束。
- 上下文超限保留完整对象/必要信息；预算耗尽后已有业务结果正确回执；缓存或向量不可用可降级。
- 供应商不返回 usage、不支持输出参数、推理 token 已包含在 completion、SDK 重试、并发预算争抢。
- Web/QQ 读取范围、会话删除、跨会话偏好以及日/月费用累计行为符合已公开约定。

### 10.3 发布门槛

| 指标 | 要求 |
| --- | --- |
| 确定性安全/正确性 | 权限、时间、确认、版本、遗忘、删除、取消和必需来源案例全部通过 |
| 端到端任务成功率 | 固定留出集观察值不低于基线；重复运行报告波动，不以高平均分掩盖关键退化 |
| 阶段 1 经济模式成本 | 非零模型场景按预先固定类别权重，单位成功任务费用目标下降至少 20% |
| 模型不变的输入精简 | 同场景输入 token 中位数目标下降至少 20%；独立报告 P90 和修复次数 |
| 摘要净成本 | 长会话专用样本中位费用目标下降至少 15%，计入摘要维护 |
| 向量检索 | 使用阶段 3 的 Recall、预算、来源和净成本门槛 |
| 零调用能力 | 固定命令、既有确定性操作和后台投递不引入额外 LLM |
| 成本真实性 | token、估算费用、未知用量分开；不同价格/模型时分别比较质量和费用 |

以上百分比是待验证的工程目标，不是本轮审计证明的收益。单位成功任务费用按“同类全部尝试费用 / 成功任务数”计算，失败、修复和摘要成本均保留；零调用场景单列，不能用于稀释平均值。如果预算不足以验证质量，只能交付离线正确性结果和待验证项，不宣称已实现真实成本降低。

## 11. 预计修改位置与迁移

| 范围 | 主要位置 | 边界 |
| --- | --- | --- |
| 模型预算与计量 | `infrastructure/model_gateway.py`、`core/model_budget.py`、运行时装配 | 用途级策略，不改业务授权 |
| 上下文 | `agents/context_builder.py`；小型用途策略模块 | 共享选择规则，不强制所有组件使用同一提示词 |
| 语义结果复用 | `agents/intent_compiler.py`、`core/intent_ir.py`、`services/semantic_task_service.py`、应用分派 | 逐领域新增受限执行，不扩大任意操作能力 |
| 工具收尾 | `agents/travel_agent.py`、`tools/reservation_tools.py` | 按已验证回执判断，支持部分成功 |
| 规划/研究 | `agents/trip_planner.py`、`services/trip_service.py`、`services/research_service.py` | 输入字段精简、局部更新和来源保留 |
| 文档/图片 | `services/document_service.py`、`services/image_context_service.py`、现有媒体存储 | 去重、按需摘要、事实缓存、质量受控缩放 |
| 会话摘要 | 新增小型摘要 Service/Repository，接入现有 store 与恢复机制 | 不新建通用向量记忆框架 |
| 可选向量 | 条件新增 embedding/检索适配器 | 单独依赖、关闭时基础功能完整可用 |
| 删除与遗忘 | `services/conversation_deletion.py`、偏好存储、派生缓存 | 立即阻断旧内容读取，迟到写入校验代次 |
| 配置与 UI | 现有 settings、配置保存白名单、Web 设置、示例配置 | 保留密钥保护与重启语义 |
| 验收 | `scripts/evaluate_tasks.py`、`evals/`、相关 tests | 生产装配一致，区分模拟与真实接口结果 |

数据库迁移优先增量加字段/表；不就地替换旧业务表。上线前使用 SQLite 一致性备份方式，保留 schema 版本。向量和摘要是可丢弃重建的派生数据，但清理仅针对已验证的索引/摘要目标，不删除原资料。

## 12. 分阶段交付与回退

| 阶段 | 可审核交付物 | 启用/回退 |
| --- | --- | --- |
| 0 | 新版调用清单、成本基线、评测装配修正、计量报告 | 仅观测；不改变模型选择与任务行为 |
| 1 | 用途级上下文、提示词变更对照、简单调用链优化、首轮基准报告 | 可切回原编排/上下文选择；不付费双跑 |
| 2 | 会话摘要与失效测试、长会话费用报告 | 关闭读取/生成即回退；业务原数据保留 |
| 3 | FTS 对照、向量实验及 Go/No-go 报告 | 默认关闭；失败回到 FTS，不影响基础安装 |
| 4 | 档位说明、预算与费用界面、兼容性与完整回归报告 | 用途模型未配置时沿用已有默认模型；设置回退后重启 |

预算模式回退不能解除用户已设置的费用上限；关闭新上下文策略也不能重新允许读取已删除、停用或越权的记忆。任何需要回到旧代码版本的操作，都先检查当前迁移兼容性，不覆盖用户在本轮之外的升级。

## 13. 审核时重点确认

1. 是否接受“均衡为新安装默认，经济可选；已有安装不自动切换模型”的配置原则。
2. 是否接受先实施阶段 0—2，向量库仅在有实证收益后可选启用。
3. 是否保持现有范围：跨 Web 会话仅共享明确保存的偏好，摘要/文件/图片/行程/研究仍按会话限制。
4. 是否接受按需摘要而非全量历史画像，以及本地向量索引不成为基础依赖。
5. 是否接受将成本降低与任务正确率一起验收，不通过删权限/时间/确认校验换取 token 降低。

如以上推荐均可接受，可按本文档作为后续实施依据；具体供应商、用途模型 ID、费率与真实评测额度在实施时依据实际配置确定，不在本草案中虚构或自动替换。
