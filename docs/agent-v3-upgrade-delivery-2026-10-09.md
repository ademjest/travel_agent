## 2. 主要行为变化

### 2.1 查询与执行

- “查天气”缺地点时保存 collecting 任务；“武汉”更新同一任务；“那明天呢”在无歧义时继承地点。
- 初始请求的时间参照保存于任务；跨午夜只补城市不改变原日期含义。用户明确提出新的“明天”则使用新消息时间参照。
- 多个地点/待补任务不静默任选；显式引用仍执行归属、状态和过期检查。
- 简单快路径只承接支持的单一只读意图，风险分析、比较、复杂否定等保留完整路径。
- 工具结果不是整个任务成功的证明。写操作回执、未完成事项和部分成功状态分别保留；内部 partial 映射既有任务状态，不新增不兼容数据库枚举。
- Amap 来源支持类型化临时错误与只读有限重试，最多首次+2次；生产 SDK 隐式重试设为0。旧字符串错误接口保留作兼容，不宣称所有第三方错误均已类型化。
- 成功只读检查点可在 Inbox 恢复时复用；Outbox 重试仅补发。重复成功写调用在再次执行前拦截。

### 2.2 摘要

- 旧自由文本摘要标为 stale，不能直接注入；不批量调用模型重建。
- 每次请求最多生成一批；按连续消息从旧到新处理，超长单条记录偏移，不把未处理部分标为已覆盖。
- 每项要求真实用户原话引用；忽略助手猜测，排除授权、密钥、结构化状态和已遗忘偏好来源。
- 发布持有短事务并重查租约、代次、依赖和全部引用；模型调用不占 SQLite 写锁。
- 引用保存来源内容哈希；原文仍保留旧引用但追加了纠正时，也会令旧摘要不可用。
- 自动检查拒绝显著的数字/单位/否定改变，但引用匹配不等于概括语义必然正确；真实关键事实/矛盾集仍须人工标注验证。
- 摘要异常、竞争或预算不足时回退有界上下文；异常回退再次检查旧摘要是否仍有效，不返回已失效副本。

### 2.3 模型入口与上下文登记

所有生产模型请求经过 ModelGateway 的完整请求预算和计量；用途名称与模型覆盖、价格实际匹配。

| 入口 / 用途 | 输入策略 | 输出处理 |
| --- | --- | --- |
| IntentCompiler / intent_parse | 原始消息+服务端任务/方案引用上下文；完整 JSON，不截序列化正文 | IR 和业务字段校验；候选模型至多一次回默认；权限不由模型决定 |
| 普通/开约提醒 / reminder_extract | 必要当前请求；连续原文验证，完整输入上限 | JSON/日期/原文依据校验，截断拒绝 |
| 查询、plan_reference、document_qa 等上下文策略 | 结构化任务投影；相关范围内文档和引用，减少无关近期历史 | 这些是上下文选择策略，不冒充额外独立模型调用 |
| 行程需求 / trip_requirement_extract | 当前需求、已有字段和必要资料；完整结构上限 | 原文依据、日期/天数和约束校验 |
| 行程生成/修复 / trip_plan、trip_plan_repair | 必要需求、POI 允许字段、旧方案和修改范围，移除重复 source_context | 最多一次校验修复；超过7天可扩展输出预留，仍不超过8192 |
| 研究 / research_plan、research_synthesis | 限定站点策略、所选来源；网页正文节选标明原长度/节选状态 | strict_sources 保留；逐项来源；失败不凭空补事实 |
| 图片 / image_extract | 当前合法图片和问题；不混入无关聊天 | 截断/不清晰拒绝，不授权业务动作；预约图结构错误至多一次修复 |
| 文档 / document_summary | 文档节选，明确原长度和覆盖边界 | 不宣称已读未覆盖部分；原文仍是问答证据 |
| 会话 / conversation_summary | 完整连续批次和有效旧引用 | 引用/代次/依赖/生命周期校验 |
| 通用 Agent / tool_reasoning、tool_answer | 当前任务、必要工具 Schema 和真实回执，每轮检查完整请求 | 写入成功后可直接确定性回复；中断保留真实回执 |
| 实验索引 / retrieval_embedding | 授权文档片段，显式有界更新，查询时不自动全量重建 | 同一网关/账本；模型维度命名空间隔离，回查来源 |

未配置已知 tokenizer 的兼容模型继续使用 `utf8-byte-bound-v1` 保守估算，不显示为精确 token。另有12 MiB完整请求字节硬上限和64000输入估算上限；图片独立估算。明细新增输入分区长度、估算方法、请求大小、finish_reason，不保存这些分区的私人正文。

### 2.4 费率和预算

复用“服务配置”入口；数字金额使用数值控件，币种使用文本控件，JSON费率映射有单独说明/示例。没有替换真实 Key 或修改正式 `.env`。

示例仅说明格式，不是真实模型价格：

```json
[{"provider":"main","model":"small-model","input":0.1,"cached":0,"output":0.2,"currency":"USD"}]
```

全局单价只用于匹配的默认模型；不同用途模型缺少匹配费率时显示未知。缺缓存细分时按普通输入保守估算，UI 明确“拆分未知”，不将已知合计0当作供应商缓存未命中。

可选金额上限需全部调用模型费率和确定币种。未知 usage 保留保守占用，缓存价格高于普通输入价时也采用更高费率预留。已有未计价历史周期不允许通过新金额开关获得“从0开始”的额度。迁移的切换门槛是旧UTC日/月周期真正结束的时刻（字段含UTC时区），不是提前8小时到来的上海午夜；生效后周期键按上海日期计算，新库立即使用上海周期。

预算账本独立于可删除调用明细：取消或会话删除后迟到的账单只结算非内容数据；usage补齐可对账，但不会恢复聊天/模型正文。结算在读取旧状态前取得 `BEGIN IMMEDIATE`，并发重复完成回调也只调整一次预留；并发与事务顺序已有独立回归。行程地点、天数、预算单位的明确简短补充也沿用已确定任务的运行预算；无关新查询不绑定旧待补任务。负数等无效usage不累计到“已知用量”，仍保留未知占用。供应商远端实际超出估算仍可能发生，因此金额控制不能取代供应商账单上限。
