# 总体优化进展回顾与下一阶段建议

日期：2026-10-16。依据总体优化方案、三批交付记录、最新源码及验收清单。本次为分析回顾，不修改业务代码、不调用收费模型、不切换正式服务。

## 1. 总体判断

总体路线仍适用。基础诊断、核心读取可靠性、摘要有限保护、研究依据和本地语义检索已取得具体成果；主要剩余工作是稳定性、真实资料与端到端验收，以及正式生效核对。不宜用一个完成百分比混合这些不同层次。

本次重新比较源码清单：当前后端与938项通过的最终报告一致，前端与58项通过及构建成功的报告一致。这是本次源码比对，不是再次执行全量测试。

最新交付记录显示正式后端未重启、前端已构建、embedding默认关闭。本次未重新检查正在运行的实例；如果用户已自行重启，需要补实际版本与功能验收记录，不能仅据旧交付状态判断当前实例。

## 3. 实施结果带来的重点调整

### 3.1 摘要：优先减少引用不足，并验证旧摘要回退

第二批5份新摘要输出，生成当时只有2份发布；最终校验器原样重验接受3份。最后的Web成功来自恢复已捕获的两版真实输出，不能算原始全Web新生成流程一次成功。

已修复的等价否定误拒不应再次当成待开发项。但模型保留旧预算/旧时间，却只引用新值的情况仍会导致整份拒绝。下一轮应比较“正文集中保留当前值”与“必要时保留新旧值及双方引用”，并检查事实覆盖与发布率；不直接放宽来源校验，也不自动增加修复调用。本次未改动用户确认的摘要提示。

O06原本已有“未覆盖纠正”的风险，现在应提升顺序：真实测试已出现增量失败后沿用旧版。仍未证明的是后续纠正退出近期历史之后会不会误用旧值。

建议先固定反例：旧预算360元，更正为320元，摘要更新失败，随后近期历史退出。若复现错误，再采用有界的未覆盖纠正补充或明确待核对状态；不要统一扩大历史窗口。

### 3.2 检索：从选模型转向证据覆盖与实际资料验证

BGE在历史100题上达到原有合成指标门槛。新16题留出中，12题有答案的Recall@5从58.3%提升到83.3%，4题无答案均未误召回。但目标主题隔离的开发/留出复用了通用干扰文档，不是严格全体文档独立；历史语料也不是全新留出。

仍漏了“每星期的第一天”与过敏原交叉接触保证的改写问题。下一步先增加同类失败、条款例外、版本冲突与无答案材料，测最终回答是否引用正确依据。BGE-M3或重排模型可作为对照候选，尚没有证据要求立即换更大模型。

长文目前对多个窗口向量取平均。代码保证各窗口被编码，但局部关键条款可能被稀释，这是待测取舍。优先比较段落/条款切分、父段补充或窗口候选保留；不要把“未截断”写成“关键事实必然召回”。

### 3.3 新增：模型与索引就绪状态

当前代码确认：模型依赖与权重在首次编码时加载；后台索引异常主要写日志；空索引查询直接返回空候选；工作线程存活不等于模型和索引可用。

因此，“已配置”“已下载”“已加载”“索引完成”应分别显示。建议复用现有服务配置与诊断入口，增加：

- 未启用、依赖缺失、加载失败、构建中、就绪等明确状态。
- 已索引/待处理片段数量、最后成功更新时间、最近失败原因。
- 区分正常无结果、门槛过滤、索引尚未完成和语义检索失败回退。

这是本轮代码暴露的可观测性缺口，不是已经发生的正式服务故障。

### 3.4 新增：发布版本与恢复结果更容易理解

本轮前端已构建，后端尚无新的正式重启验收，可能出现新页面访问旧接口的部署中间状态。建议复用已有“待重启”提示，补充实际前后端版本、能力是否可用，并在版本不匹配时给出明确提示。

诊断当前保留所有异常，最后任务完成时提示“有降级或异常记录”。后续可以进一步区分“曾失败但已恢复”“仍在降级”“最终失败”“结果未知”，将关键问题和已知处理建议放在时间线前面。这里应使用明确规则和已有记录，不依赖额外模型猜原因。

### 3.5 后续有规模证据再做索引性能优化

当前索引维护每轮读取范围内片段并比较内容哈希；查询读取该范围向量再计算相似度。对本地少量资料简单可用，尚没有正式规模下的性能证据。资料增加后应先测耗时和内存，再考虑变更队列、缓存或专门索引；暂不据此引入独立向量数据库。

## 4. 推荐后续顺序

1. **收尾当前交付**：补正式运行版本和功能验收；embedding依赖与索引就绪状态先说明白，保持可独立开关。
2. **摘要可靠性优先**：未覆盖纠正/旧版回退反例，随后完整Web新生成与独立重复。新的付费测试沿用原方案登记新额度，既有额度不重置。
3. **扩展查询可靠性**：搜索和网页读取统一错误、重试与取消边界。
4. **资料与事实质量**：实际旅行资料的检索和回答评测，条款切分、版本/有效期、旧报告与草稿到规划的依据传递。
5. **效率、维护及综合验收**：质量稳定后评估总成本和模型分工，完成多入口契约试点、恢复/投递交错与L2发布核验。

这是本次回顾形成的建议排序，不代表这些剩余项已经实施或验收。
