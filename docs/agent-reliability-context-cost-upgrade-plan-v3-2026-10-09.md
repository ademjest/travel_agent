## 3. 范围、不变量与非目标

### 3.1 本轮范围

- 简单查询、工具循环和领域服务共享的任务接续与结果契约。
- 摘要生成、重建、引用、失效和生命周期。
- 用途上下文、结构化裁剪、输入/输出预算。
- 结构化错误、有限重试、幂等和部分成功。
- 模型费率快照、估算来源、预留/实际消耗及累计。
- 生产装配一致的离线评测和受限真实评测。
- 以数据决定的小模型、摘要、缓存及语义检索实验。
- 必要的设置说明、状态和报告修正。

### 3.2 必须保持的不变量

1. 权限、身份和资源归属由服务端确定，资料、摘要和模型不能扩大授权。
2. 本轮明确要求优先；当前草稿和已确认业务状态是准确来源；长期默认仅在适用时补充。
3. 用户的早期有效约束不能因较旧而丢弃；新纠正要显式覆盖旧值。
4. 写操作继续按现有业务规则确认，不因快速路径、模型升级或重试绕过确认。
5. 业务动作、任务状态和可恢复回复保持既有事务边界；网络和模型调用不占用 SQLite 写锁。
6. 取消、超时、租约替换、会话删除后，迟到结果不得重新获得业务写入权。
7. 费用记账可在业务撤销后继续，但只能写非内容计量数据，不能复活已删除正文和调用明细。
8. 重放事件不重复执行已确认写操作；投递重试不重新生成业务内容。
9. QQ 文档群共享等既有范围继续保留；成员私人偏好、任务与摘要按原作用域隔离；Web 与 QQ 不自动互通。
10. 开关回退不撤销已有费用限额、遗忘、删除和权限约束。

### 3.3 非目标

本轮不包含 MCP 接入、自主 Multi-Agent、微服务拆分、跨平台账号绑定、模型微调、自动预约支付或通用文件编辑 Agent。Web 整体拆组件不是前置条件，只改本方案需要的配置与状态展示。

## 4. 目标执行链与最小共享契约

### 4.1 目标执行链

```text
统一 ChatEvent + 当前执行权
    → 识别/绑定待补任务和用户引用
    → 固定命令或一次结构化语义提取
    → 字段来源、范围、时间与业务校验
    → 选择快速查询 / 专用服务 / 工具循环
    → 统一业务结果（含动作回执与状态更新）
    → 服务端事务提交任务及可恢复回复
    → Outbox 投递
```

“快速”只改变执行步骤数量，不改变上下文来源、缺项保存、版本检查和结果真实性。

### 4.2 两种最小内部契约

不一次重写所有服务。先增加小型不可变结构，并用适配器兼容现有返回字符串/AgentResult。

| 契约 | 建议字段 | 边界 |
| --- | --- | --- |
| TaskContext | 平台/读取范围、task_id/version、初始请求、本轮输入、slots、missing_slots、时间参照、目标版本、字段来源 | 服务端构造；不让模型指定身份 |
| ExecutionOutcome | completed/needs_input/partial/failed/cancelled、TaskUpdate、成功与失败回执、缺项、用户回复、证据引用 | 应用在适合的事务中持久化，不由模型自由声明完成 |

工具层保留 ToolResult，增加必要的结构化错误和 Artifact 元数据；它不是整个业务任务的完成证明。

内部新增 partial 不立即强改所有数据库状态枚举。迁移时明确哪些字段只是执行结果，哪些映射到现有 travel_tasks/inbox/outbox 状态，避免把“业务部分成功”混成“消息未投递”。

## 5. P0：优先修复四个一致性问题

### P0-01 查询快速路径与慢路径状态一致

**目标案例**

- “查一下天气”→“武汉”→“那明天呢”：只追问一次地点，并继承武汉。
- “明天武汉天气”发生在 23:59，次日补充信息时仍保留原请求时间参照；用户主动说新的“明天”则使用新消息参照。
- 两个待补任务同时存在时，依据实际引用/明确选择绑定；不静默取最近一条。
- 失败、取消、过期任务不被无关新问题重新激活。

**实施设计**

1. 在模型调用前，用现有 read_task_continuation、TaskRepository 和引用关系解析当前候选任务。
2. 快速查询接收服务端 TaskContext，而不是只拿当前文本。
3. 新字段要能对应当前原话；继承字段必须来自已授权且有效的任务，并记录来源。不能为复用历史而放松原文检查。
4. clarify 保存 TaskUpdate：初始请求、已知字段、缺项、时间参照、task_id 和 expected_version。
5. 查询成功保存已使用参数和 completed 状态；查询失败保存真实错误和接续策略，不把失败文本作为成功结果。
6. 与现有 Agent 慢路径共享 TaskUpdate 生成及时间处理，不复制两套分支。
7. 快速路径仅处理支持的单意图只读查询；多意图、复合否定、额外解释需求转既有完整路径，并保留原始请求，不能丢弃其他动作。
8. 重复事件通过现有 task_event_results 和 prepared_reply 复用结果，防止生成多个待补任务。
9. 无法可靠解析时在当前任务上下文中追问；不能让 fallback 越过业务拒绝去执行同一操作。

**主要修改位置**

[semantic_task_service.py](../services/semantic_task_service.py)、[tasks.py](../core/tasks.py)、[task_repository.py](../infrastructure/task_repository.py)、[travel_agent.py](../agents/travel_agent.py)、[bot_application.py](../app/bot_application.py)。

**验收**

- 单一完整自然语言查询：无回退时 1 次语义模型调用；固定命令仍为 0 次。
- 缺字段时真实数据库存在 collecting 任务，补全后更新同一任务版本。
- 快慢路径对同一输入形成等价的任务状态、查询日期和工具参数。
- 覆盖重启、重复消息、跨午夜、多任务、换话题、越权引用和取消。
- “创建业务 + 存回复后投递失败”只补发，不重新查模型。

### P0-02 摘要失效、并发与重建

**根因**

latest 只返回 active；stale 后 previous=None 令 expected_version=0，但数据库保留 version>0，CAS 永远失败。

**设计**

1. 分离“可读摘要”和“重建元信息”接口。用户上下文只能取得有效摘要；重建逻辑始终能读取当前版本、失效代次和覆盖边界。
2. 每次失效增加 generation/版本；摘要记录标为 stale，当前请求不再注入。
3. 摘要生成前领取有到期时间的生成租约，绑定 scope、owner、目标代次、输入边界和输入指纹。相同输入只允许一个生成者。
4. 模型调用在事务之外执行；发布时在同一事务重新验证 generation、租约、源消息存在、偏好版本和会话仍有效。
5. 失效后的重建不复用已作废摘要文字。必要时从合法原始消息重新构建，但必须排除已遗忘偏好/已删除来源，不能通过重扫历史恢复它们。
6. 竞争失败不再立即重跑；返回新有效摘要或空摘要，按失败原因设置冷却时间。取消/预算耗尽立即结束生成。
7. 新偏好、删除方案/资料、源纠正和相关业务版本变化触发失效。首版无法精确判断依赖时，保守失效该会话摘要。
8. Web 跨会话偏好变化可使同一用户相关会话摘要失效；QQ 仅影响相应平台/成员/群范围。
9. 首版用会话内容代次和偏好版本作粗粒度依赖；有明确收益后再做逐条精细依赖图。

**建议增量字段**

generation、covered_from_id、covered_to_id、dependency_fingerprint、preference_version、lease_token、lease_until、last_attempt_fingerprint、retry_after、last_error_code。字段以实现评审收敛，避免重复维护与现有 version 同义的状态。

会话创建/删除的生命周期检查继续由现有 WebLifecycle 提供；后台任务的 ExecutionScope 不能替代独立的摘要失效检查。

**验收**

- active→stale→重建成功，版本单调递增。
- 两个 worker 对相同输入至多启动一次摘要模型调用。
- 生成期间修改偏好、删除来源或会话，旧生成结果不得发布。
- CAS 失败不形成每轮生成却无法保存的调用循环。
- 重启回收过期租约；summary 关闭时不读取也不生成。
- 故障和预算耗尽不妨碍原业务继续使用有界上下文。

### P0-03 摘要完整输入、正确覆盖与可追溯输出

**输入处理**

1. 删除对序列化 JSON 的字符尾切；按完整回合从旧到新选择连续批次。
2. 必须先计算固定提示、旧有效摘要、本轮批次和输出预留。放不下的回合留给下一批，不标记为已覆盖。
3. 单个超长消息单独分块，记录 message_id + chunk_index/范围；未处理完前不推进整条消息覆盖游标。
4. 覆盖游标只指向实际处理并验证成功的连续边界；来源哈希也只计算该批真实输入。
5. 每个用户请求最多触发一次摘要生成/更新。批次积压不通过递归无限压缩解决。
6. 与摘要重叠的近期历史按来源 ID 去重，保留最近必要原文。

**输出处理**

建议返回结构化条目，而非单个自由字符串：

```json
{
  "items": [
    {
      "kind": "decision",
      "text": "用户希望保留周三下午的自由活动时间",
      "sources": [{"message_id": 123, "quote": "周三下午留给我自由活动"}]
    }
  ],
  "open_questions": []
}
```

- 服务端确定输入来源白名单；每项必须有合法来源和真实原文片段。
- 不接受仅有一个合法引用、其他内容没有来源的输出。
- kind 限定 decision/correction/unresolved/reference 等少量枚举。
- 数字、否定、日期、预算单位出现变化时回查原文或结构化状态。
- 已结构化任务、偏好、行程和方案仅保留引用，不重复制造新的权威副本。
- 原文匹配只能证明引用存在，不能证明概括必然正确；真实摘要评测必须人工标注关键事实和矛盾。
- 暂时无法可靠核验的条目舍弃或回查；安全/授权/身份结论不得由摘要提供。

**旧摘要迁移**

旧文本摘要无法满足逐项来源要求，按版本标为待重建且暂不可注入，不批量自动调用模型。保留可审计元数据及原始来源，按需重建。

**验收**

包括超长首回合、跨批次否定、末尾小消息、伪造引用、引用真实但结论相反、助手猜测、两名成员陈述冲突、删除后重建。要求覆盖边界无跳跃、无重复付费处理成功批次、关键约束不被无声丢弃。

### P0-04 费用零值、模型费率与历史估算边界

**计算规则**

- 缺省只判断 None，0 是合法值。
- 使用 Decimal 或等价定点十进制进行货币计算，展示时统一舍入。
- 对 usage 做非负和类型检查；cached_input 不得大于 prompt。异常 usage 标为不可准确计价，不静默制造负成本。
- 若 reasoning 已包含在 completion 内，不重复计费。
- 未知和估计明确分开，不把缺失缓存拆分显示为供应商报告“缓存为 0”。

费用规则示意：

```text
普通输入费 = (输入 token - 已知缓存输入 token) × 普通输入单价
缓存输入费 = 已知缓存输入 token × 缓存单价
输出费     = completion token × 输出单价
```

缺失缓存拆分时可按全部普通输入保守估算，并标记 conservative；未知供应商计价语义时不套用上述公式冒充准确费用。

**费率选择与快照**

1. 费率按 provider 配置标识 + 实际 model_id + 费率版本匹配。
2. 当前全局费率迁移为默认模型对应的默认 profile，不能自动套给所有用途模型。
3. 未配置用途模型价格：继续允许 token 限额下调用，但费用显示未知；启用强制金额配额时则要求补齐价格。
4. 每次调用在预留时冻结实际模型、费率、币种、日期、配置版本和计价规则；完成时用该快照结算。
5. 同名模型但不同 provider 不混用价格；不同币种分组，不默认做汇率换算。
6. 新增最小费率配置入口，复用安全设置白名单、启动生效规则和版本冲突；可选结构化费率映射不引入第二套密钥管理。

**历史记录**

- 已持久化正常估算保留原快照。
- 旧记录没有模型对应价格或币种依据时，报告明确未知/推定。
- 零缓存价 bug 影响的旧记录只在源 usage 和快照完整时提供“原估算/修正估算/差额/规则版本”；不静默改写为供应商账单。
- 缺源数据的历史记录不能精确修复。重算本地报告也不能重置已执行预算累计。
- 对历史累计纠偏使用独立版本化调整记录，禁止删除旧账后重新累计导致重复收费展示。

**验收示例**

| 输入条件 | 预期 |
| --- | --- |
| prompt=100、cached=100、completion=0；输入价1、缓存价0、输出价2 | 费用精确为 0 |
| prompt=100、cached=40、completion=20；输入价1、缓存价0.5、输出价2 | 费用为 0.00012 |
| cached 细分缺失 | 标记缓存拆分未知，必要时保守估算 |
| prompt 或 completion 缺失 | 不能显示确定的实际费用 |
| 用途模型未配置价格 | 不沿用不匹配模型价格 |
| 改价后查看旧已计价记录 | 使用原快照 |
| 多币种/负数/NaN/Infinity/异常 token | 分币种或拒绝无效配置/计量，不能错误汇总 |

## 6. P1：执行、上下文和评测形成闭环

### P1-01 各模型入口共享上下文选择与预算规则

**设计原则**

共享权限、选择、去重、预算和观测，允许不同组件保留适合自身用途的输出结构。ContextPolicy 中定义了用途不代表已经接入，必须逐入口登记并测试。

| 调用用途 | 必需输入 | 优先移除 | 验证重点 |
| --- | --- | --- | --- |
| intent_parse/reminder_continue | 本轮原文、唯一候选任务、已知字段、缺项、时间参照 | 群闲聊、全文资料、全部旧行程 | 不能截掉日期/否定/原文依据 |
| plan_reference | 稳定方案编号、类型、天数、版本、本轮引用 | 全部方案正文 | “最开始”不能因裁剪重新编号 |
| travel_lookup | 查询参数、地点接续、引用 | 无关偏好与文档 | 缺项保留，日期解释一致 |
| document_qa | 相关原文、来源/版本、必要历史 | 无关概要 | 无匹配可返回空，泛化总结走明确文档读取 |
| trip_requirement_extract | 当前需求、本轮变化、必要旧字段、资料引用 | 完整研究正文 | 旧约束与新纠正不混淆 |
| trip_plan/trip_edit | 有效约束、必要 POI、受影响日及边界、版本 | 电话、冗余 metadata、重复 source_context | 保留必去点、酒店餐饮要求和跨日一致性 |
| research_plan/synthesis | 问题、同目的地来源策略、选中证据、时效与引用 | 全部网页、重复宿主内容 | strict_sources 不被放宽 |
| image_extract/document_summary | 当前合法材料、问题、必要提取格式 | 无关聊天 | 同图不同问题不复用旧答案 |
| conversation_summary | 有效旧摘要引用、连续新回合、失效约束 | 结构化数据冗余副本 | 见 P0-02/03 |
| tool_reasoning/tool_answer | 当前任务、完整工具回执、必要工具 Schema | 无关工具和重复原文 | 结果成功与用户回复一致 |

**实施措施**

- 用显式字段投影替代截断 slots JSON。
- 给最关键结构预留预算，再按完整片段填剩余空间；必要字段放不下时缩小任务或追问。
- 每次工具循环检查完整请求，不只检查第一次输入。
- 已知编码用对应 tokenizer；未知兼容模型记录估算方法/版本和误差样本。保留独立硬字节上限，图片估算单独标注。
- 输出限额按结构复杂度调整，例如 14 天行程与 1 天不共用过小固定值；JSON 截断识别 finish_reason，在总额度内最多一次受控修复。
- 语义编译/规划/摘要各自输出上限和修复上限清晰，不能叠加成无界重试。
- 成功快速路径不再重复解析；复杂请求可多次调用，但每次都有用途和输入选择理由。
- 规划方案历史回填记录水位，避免每条消息扫描全部历史；读取可分页但保留稳定 ordinal。
- 范围外或未确认资料不进入模型；工具和网页资料继续按非可信数据处理。

**验收**

各生产用途都有契约测试；大任务边界完整；同一消息不会在群历史/个人历史/任务摘要中重复注入；统计各用途输入构成、被裁剪数量和理由，不记录私人全文。

### P1-02 错误、重试、部分成功与无进展控制

**错误契约**

在现有 ToolResult 基础上统一：
category、retryable、retry_after_seconds、effect_status（none/committed/unknown）、resource_id、state_version、operation_key、artifact metadata、用户安全错误说明。

来源客户端应返回类型化错误。中文文本匹配只作旧接口兼容，并纳入逐步移除清单。

| 类型 | 策略 |
| --- | --- |
| invalid_argument/schema | 允许一次有依据的参数修正；不重复相同非法参数 |
| needs_input | 保存缺项任务并结束本轮 |
| permission_denied/not_allowed | 结束该动作，不通过换模型绕过 |
| version_conflict | 重新读取并要求核对新预览，不提交旧写入 |
| timeout/temporary_upstream | 只读有界退避；写请求先核对幂等回执 |
| rate_limit | 在任务剩余期限内尊重 Retry-After，可让出执行权 |
| unknown_effect | 不盲重放写操作；核对状态或提示需人工确认 |
| budget_exceeded/cancelled/revoked | 停止新增调用，保留真实成功回执 |

**重试预算建议初值**

- 独立只读外部调用：首次 + 最多 2 次重试。
- 模型输出校验修复：最多 1 次。
- 小模型升级默认模型：最多 1 次，与修复共享任务预算，不能每层重新获得额度。
- SDK 网络重试：明确由 SDK 或网关一层负责；若保留 SDK 的 1 次重试，应计入物理尝试上限/未知成本标识。
- Inbox 恢复最多次数继续沿用现有上限；恢复复用成功检查点，不重做已完成调用。
- Outbox 只重试投递，不重新调用模型。

以上为初值，需用超时与限流故障注入验证，总 deadline 和事件预算始终优先。

**幂等与进展**

- 写调用执行前按 operation_key 查询已提交回执；同参数不代表永远允许再次执行。
- 成功结果版本/内容指纹、待补字段变化、候选变化都可作为进展。
- 相同失败重复且无新信息时停止；按错误类别区分必要重试和无意义循环。
- 不只比较每轮可能变化的时间戳，签名排除无意义展示字段。
- 任一步停止都返回成功动作清单与未完成动作；最终文字生成失败不能把已提交业务说成全部失败。
- 相互依赖/互相冲突的写动作串行；独立只读仍可按现有限额并行。
- 预约批量修改继续保留事务一致性；“原子批量操作”和“多个独立操作部分成功”明确区分。

**Artifact 补齐**

- ToolResult 用结构化 artifact_id 声明可读结果；不通过正文出现“TA-”开启工具。
- 保存时记录 original_length、stored_length、truncated、来源、scope、版本及有效期。
- 超过存储上限时明确说明，只在可复查原源时提供进一步读取，不能称“完整结果”。
- 分页验证当前权限、来源状态、游标和大小上限；重复页受进展控制。
- 资料变化、删除和会话取消时禁止迟到发布；读取 Artifact 仍占用工具总预算。
- 业务错误即使长度很大仍是 failed，不因截取展示文本而丢失错误性质。

### P1-03 计量、预留、结算与删除一致性

P0 先纠正费用公式；P1 解决计量生命周期。

1. 明确区分真实 usage、估算输入、硬字节限额、在途预留和已结算消耗；UI 不把 UTF-8 字节保守估算标成准确 token。
2. 每次调用在短事务中预留，冻结模型/费率/周期桶；完成后原子结算一次，重复回调不重复累计。
3. 已返回完整 usage：结算为实际量并释放多余在途预留；预估不足时记录实际超出并阻止后续超额调用，不能承诺远端账单绝对不超限。
4. 超时或 usage 未知：保留保守占用、记录 unknown，不直接按 0 释放；可在取得供应商回执后对账。
5. 业务取消或会话删除后仍可能发生费用：独立非内容调用账本保存足够结算的信息，与可删除 model_calls 明细解耦。
6. 摘要、模型回退、格式修复、检索 embedding 均归属原业务运行预算；多条补充消息不应无限重置业务任务预算。
7. 首版固定应用预算时区为 Asia/Shanghai，并明确显示。现有 UTC 累计升级必须保留：实施时选择下一个预算周期生效或进行有明细依据的迁移；不能改日期切分后释放当日已用额度。
8. 旧 reserved_tokens 不可无标记转换为真实消耗；为预算算法与计量单位记录版本。旧周期延续原保守语义，新周期使用新结算，避免假精度。
9. 金额日/月配额是可选能力：仅在全部候选模型费率、币种和计价语义明确时提供。未补齐时提供 token/调用限额；若用户已要求硬金额控制，缺价格时停止该计费调用并提示补齐。
10. 多币种配额分别统计，不用未经配置的汇率凑总额；总预算按已确定本地使用者/平台数据目录执行，沿用 Web/QQ 隔离。
11. 历史费用回算只展示、不修改原累计；必要纠偏采用可追踪调整项。
12. 报告的聚合应优先在数据库侧完成、明细分页，避免设置页每次扫描全部调用；缓存报表不能吞掉未知状态。

**验收**

并发预算争抢、长调用跨午夜、SDK 重试未知、超时后迟到成功、重复完成、删除会话期间完成、清理明细后累计仍在、费率切换、多模型和多币种必须覆盖。无法知道远端 usage 的调用必须明确保留不确定性。

### P1-04 生产装配一致的评测与发布门槛

**装配**

- 为 build_runtime 增加最少的模型客户端/数据源/时钟/投递依赖注入参数；生产与测试使用同一装配逻辑。
- 使用已配置形态的假模型客户端启用全部生产组件，禁止先用空配置屏蔽语义层再手工补部分路径。
- 假模型按 purpose 和场景阶段返回，不靠“恰好第 N 次调用”掩盖入口变化。
- 接入 Web API→Inbox worker→应用→领域服务→Outbox→展示数据；同时覆盖 OneBot 和官方 QQ 的适配契约。
- 所有外部网络由 mock/snapshot 替代；离线执行不加载正式 .env。
- 注入固定 clock，禁止基准依赖当天日期导致过期和恢复测试漂移。

**固定合成业务集**

复用现有 120 案例并补齐，不要求全部重写。建议形成至少 160 个多轮场景：

| 类别 | 建议数量 | 必含 |
| --- | ---: | --- |
| 快速查询与多轮接续 | 30 | 缺项、跨午夜、两任务、复合意图 |
| 行程/方案/酒店餐饮 | 30 | 采用方案、跨日约束、品牌、预算单位、旧预览 |
| 提醒/调度/投递 | 25 | 定时查询、过期、重放、投递失败 |
| 文档/图片/研究 | 25 | 无匹配、来源严格限制、图片不清晰 |
| 记忆/范围/遗忘/删除 | 25 | 摘要重建、并发失效、跨成员隔离 |
| 预算/取消/恢复 | 25 | 日月边界、迟到结果、未知 usage、幂等 |
| 合计 | 160 | 调试集与留出集预先固定 |

上述数目是覆盖计划，不能用复制同类简单案例凑数。旧报告与新报告记录装配版本并分别存档，不能直接以旧 120/120 对比新成本。

**证据等级**

- 单元测试：局部逻辑正确。
- 生产装配离线测试：调用链、状态、事务和故障路径正确。
- 真实合成任务评测：语义质量、实际 usage 和模型波动。
- 正式环境验收：生效配置、数据迁移、健康与关键任务可用。

每份报告记录源码/Prompt/模型/配置/数据集版本、测试环境、估算方法和未知项。删除或匿名化样本正文不应让统计被误称为完整账单。

**报表工具**

evaluate_token_memory 分离为纯只读报告与显式迁移路径。只读路径用 SQLite 只读连接，不创建表、不触发 MemoryStore 初始化；无新表时说明缺少能力。报告覆盖的是当前库观测，不能拿空临时库报告证明生产成本已下降。

## 7. P2：在可靠基线上做四类实验

### 7.1 共同实验协议

- P0 全部通过、P1 生产装配基线稳定后开始。
- 先固定当前默认模型的基线，再一次改变一个因素：上下文、模型、摘要或缓存。
- 使用合成输入与固定工具证据；调试集和留出集分开，避免用同一套题调优并汇报提升。
- 记录首 token（可测时）、总耗时、P50/P90、调用与物理尝试、输入/缓存/输出、修复率、成功率和失败成本。
- 单位成功任务费用 = 同类全部尝试费用 / 成功任务数；失败、回退、摘要与索引费用都计入。
- 小样本报告置信区间/波动和适用范围；不以平均分遮盖关键安全失败。
- 功能构建不意味着正式启用。达不到门槛时交付 No-go 原因，保留基线。

**真实实验额度表（执行前补齐）**

| 参数 | 执行前确定内容 |
| --- | --- |
| provider/模型 | 基线和候选的实际标识、支持能力 |
| 价格 | 每个模型的输入/缓存/输出价格、币种、版本 |
| 样本量与重复 | 首批建议 20 个探针案例，每案基线/候选各 1 次；通过后留出集至少 60 个，关键样本重复 3 次 |
| 调用上限 | 基线与候选、回退、修复、摘要和 embedding 分别上限 |
| 金额硬上限 | 用户认可的具体数额与币种，未确定前只做离线评测 |
| 数据范围 | 合成案例和固定公开证据，不默认上传正式私人会话 |
| 停止条件 | 达预算、鉴权失败、格式不兼容或关键安全退化即停止 |
| 交付 | 原始非敏感计量、聚合指标、差异案例、Go/No-go |

金额计划按最坏请求量保守计算：样本×重复×(基线与候选调用预算)+允许的回退/修复/摘要/索引。未知 usage 占用保守预留。测试全过程不自动充值或扩大额度。

### P2-01 用途模型与调用效率

1. 首批只试 intent_parse，默认模型保留；同 provider 的用途模型优先，跨 provider 路由不是前提。
2. 先跑 schema、来源、任务状态和业务动作校验；基础 IR 合法但字段不支持/语义冲突时，返回结构化拒绝原因。
3. 可由更强模型修复的歧义至多升级一次；权限、用户缺项、预算耗尽、取消不能靠升级解决。
4. 实际执行仍用相同服务端校验，候选模型不拥有额外工具和权限。
5. 对“JSON 合法但选择错业务”的样本单列语义错误率，不能只统计解析通过率。
6. intent_parse 通过后再评估 research_plan、摘要等用途；视觉和复杂行程不默认降级。
7. 规划输入去重、POI 字段精简和确定性回执收尾先独立测量，避免把调用链收益错误归因于更便宜模型。
8. 14 天行程、长 IR、复合变更检查输出截断和修复成本；稳定收尾不再请求会被丢弃的模型文字。

**建议启用门槛**

关键权限/时间/否定/确认案例零退化；留出集端到端成功率观察值不低于基线，并报告波动；单位成功任务费用下降目标 ≥20%；P90 延迟不劣于基线超过 10%。若费用较低但质量/延迟明显退化，保持原模型。升级率只作诊断，不单独作为成功指标。

### P2-02 摘要质量与净收益

比较三组：当前有界上下文、结构化状态优先但无摘要、同策略加摘要。

样本覆盖至少 30 个长会话和 20 个短会话负对照，每个长会话含超过最近窗口的关键否定、纠正、任务切换和旧方案引用。

- 摘要在本轮确需早期非结构化内容且超过预算时才触发，不因消息数足够就在无关天气问题中生成。
- 阈值不机械沿用 8 回合/9000 字符；通过数据调优，并保留单次生成和冷却上限。
- 摘要维护成本分摊到整个会话后评价，不只比较某一轮输入量。
- 模型选择、摘要 Prompt 和上下文策略分开消融。
- 按条目统计来源有效率、关键事实保留率、矛盾/幻觉、重建成功率和重复生成。

**门槛**

短会话不新增摘要调用；关键约束/删除遗忘安全集全通过；长会话总净费用下降目标 ≥15%，最终任务质量不低于无摘要结构化基线。未通过时摘要继续默认关闭，保留实现和缺陷修复。

### P2-03 Prompt Cache

1. 构建稳定系统前缀、稳定输出协议和少量用途工具包；动态日期、任务和结果置后。
2. 比较固定工具包与最小动态裁剪；总输入、命中、延迟和费用一起衡量。
3. 区分应用工具缓存、模型前缀缓存、SDK 连接复用。缓存命中只以供应商返回为依据。
4. 冷/热请求重复、随机交错条件，记录缓存保留时间和路由不确定性；避免只挑连续重复问题产生漂亮数字。
5. 命中指标分别报告：提供缓存细分的调用覆盖率、其中 cached>0 的比例、cached/prompt token 比例。字段缺失为 unavailable，不算 0%。
6. 首 token 延迟仅在流式或真实时间指标可获得时统计；非流式总耗时不能冒充首 token。
7. 暂不强加供应商专有参数；通过已核实能力配置适配，兼容服务不支持则普通调用。

**门槛**

输出质量不变、额外输入未抵消缓存收益，目标热请求端到端费用或可测预填充/首 token 延迟改善 ≥10%。不支持缓存时交付 Not supported，不列为功能失败，也不宣称提效。不得为命中跨用户混用业务缓存。

### P2-04 检索指标修正与语义检索实验

**先修评测，再选择技术**

当前 hash-ngram 保留为 lexical-hash 实验基线，在 UI/文档中明确不是语义 embedding。不得用现有 5 个样本的 100% 作为向量能力的证据。

**评测接口**

- 候选检索与最终上下文选择分开：检索可返回 top-k；上下文仍按预算取少量片段。
- 使用 chunk_id 作为标签，必要时另统计 document_id，不把同文档任意片段都当正确。
- Recall@k = 检索出的相关片段数 / 标注相关片段总数。
- Hit@k = 是否至少命中一个相关片段；与 Recall@k 分开。
- MRR/nDCG 可辅助比较排序；无答案样本另统计误召回/拒答率。
- k=5 时检索接口必须真正返回最多 5 个候选，不能先裁为 2 再声称 Recall@5。
- 检索收益还要检查最终答案引用正确率与证据 token。

**数据集**

建议至少 100 个查询、足量干扰文档：精确匹配 25、同义表达 25、多片段组合 20、无答案 15、时效冲突 15；另设跨成员/会话、删除、权限变更安全集。固定标注和留出集，避免全部小库只有两篇文档。

**实验顺序**

A：结构化精确读取 + 改善中文切词/FTS。
B：A + 现有哈希字符特征（只作廉价基线）。
C：A + 合适的语义 embedding。

C 在 A 仍有可复现同义漏检时启动。默认先实验一个提供者：本地模型须明确下载体积、许可证和 CPU/RAM；远程服务须明确数据范围与费用。向量可在测试规模用 SQLite 保存并精确计算相似度，规模达到瓶颈后再决定 sqlite-vec，避免将外部数据库作为基础依赖。

- FTS 与向量按 RRF 等排名融合，不直接相加不可比原始分数。
- 来源表是权威数据；索引键包含作用域、源 ID/版本、内容哈希、embedding 模型/维度。
- 查询前过滤范围，查询后再验证源存在与有效；删除先阻断读取再异步物理清理。
- 模型/维度变化使用独立命名空间，失败可回 FTS；不在模型执行线程内全量重建。
- 初版只索引授权文档片段。扩展研究/图片证据前补齐对应来源和时效模型；不索引所有聊天。
- 统计首次索引、增量更新、查询 embedding、存储、检索和下游生成全成本。
- 首批不加 LLM query rewrite/reranker；有明确收益后单独评估。

**门槛**

在同义/跨片段留出集 Recall@5 提升目标 ≥10 个百分点；总体引用正确率不下降；无答案误召回不增加；权限/删除安全案例全通过；最终证据 token 不超预算；在事先声明的使用量下总成本可接受。不满足任一关键门槛则 No-go，FTS 保持默认。

## 8. 数据迁移、部署与回退

### 8.1 最小增量迁移

| 数据 | 迁移方向 | 旧数据处理 |
| --- | --- | --- |
| travel_tasks | 尽量复用 slots/version，添加必要字段来源和运行关联 | 旧记录按兼容读取，不用模型批量补猜 |
| conversation_summaries | 增加代次、来源条目、覆盖边界、生成状态/租约 | 旧文本摘要标为待重建；保留原始来源 |

| 预算账本/累计 | 在途预留、已结算、未知占用与幂等完成 | 独立于会话内容删除；旧周期不重置 |
| tool_artifacts | 来源/长度/截断/版本/有效期 | 旧记录标记来源信息不完整，不假设永不过期 |

| 配置 | 单 provider 模型费率映射、必要 rollout 开关 | 默认沿用已配置模型；不修改真实 Key |

具体表/字段在对应阶段设计评审确定，优先扩展现有实现而非新建重叠状态表。

### 8.2 上线顺序

1. 固定源码与依赖基线；在独立 Python 3.11 环境及现有支持环境验证，避免变更共享 Conda 依赖。
2. 使用 SQLite backup API 生成一致性备份，记录 schema 与应用版本并验证可恢复。
3. 在临时副本跑迁移和回归；迁移不能调用模型或外部 API。
4. 选择任务空闲窗口；停止当前实例、备份、迁移、启动同一数据目录的一份服务。
5. 先启用 P0；按领域启用 P1；P2 模型/摘要/检索维持已验证默认值。
6. 检查健康接口、设置生效状态、一条查询接续、一条行程预览、提醒调度与删除。
7. 记录上线结果和备份位置；不默认执行远程发布、Git 提交或 PR。

### 8.3 回退

- 查询快速路径出错：关闭该领域快速执行，但保留 P0 任务持久化与可靠接续，不退回已知缺陷。
- 小模型出错：取消用途覆盖，使用原默认模型，业务状态与配额保留。
- 摘要出错：停止读取/生成，保留有界原文和结构化状态；不向旧程序提供新格式的未验证摘要。
- 检索出错：回退 FTS；过期和权限过滤不可关闭。
- 成本/预算模块故障：停止新的受限计费调用并返回明确原因，不能通过关闭检查绕过已设限额。
- 数据迁移回退先验证旧代码可读取新 schema；已有新业务写入后不能直接恢复整库旧备份而丢失用户新数据。
- 各开关的默认、保存/运行态和回退效果必须有文档，避免多个开关组合形成无法解释的路径。

## 11. 风险与取舍

| 风险 | 取舍与缓解 |
| --- | --- |
| 统一契约改动面过大 | 从查询领域和现有结果适配开始；不重写全部服务 |
| 摘要事实难自动验证 | 逐项来源、关键约束回查、人工留出集；默认关闭直到验证 |
| 摘要依赖过细难维护 | 首版保守失效整个会话；用数据决定是否细化 |
| 多层重试放大费用 | 一个业务运行总预算，修复/升级/恢复共用，投递分离 |
| 语义模型合法但理解错误 | 业务校验回流、语义错误样本、默认模型有限升级 |
| 旧预算算法无法精确换算 | 版本化周期切换，保留历史保守累计，不虚构精确结算 |
| 测例太简单掩盖检索问题 | 候选检索与上下文解耦，增加干扰、多相关、无答案和范围集 |
| 共享工作区已有修改 | B0 固定哈希和差异，增量改动，不自动回退或提交 |
| 付费验证依赖未定 | 先完成离线工程；提交具体调用与金额清单后再运行 |
| 新模型/检索没有净收益 | 交付 No-go，基线保留；不为了“完成升级”强行启用 |
