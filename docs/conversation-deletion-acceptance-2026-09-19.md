# 会话删除功能交付记录

日期：2026-09-19  
依据：[已审核方案](conversation-deletion-plan-2026-09-18.md)

## 已交付

- 会话列表和当前标题栏的删除按钮、关联数量摘要、不可恢复确认弹窗。
- Cookie／CSRF／Origin 保护的删除接口，重复删除返回同一个作业，不重新执行业务。
- 短事务建立删除边界，撤销执行和投递权，停止普通提醒、预约提醒、定时查询及规则监测。
- 清理 Web 消息、上下文、文档与全文索引、图片、行程版本、任务、工具结果、通知和可归属模型调用明细。
- 迟到模型结果和失败通知不能重新生成该会话数据；已删除会话接口返回 410，已清理的附件和任务 ID 可以返回 404。
- 文件发布意图持久化、共享图片引用检查、数据目录边界与 junction／symlink 检查。
- 文件占用等错误显示清理失败，支持明确重试；进程重启后恢复 pending／cleaning 作业。
- 清理完成后只保留会话 ID、状态与时间等最少标记，清空文件与事件清单，不保留会话标题。
- 当前草稿和界面清理、跨标签页同步、迟到响应丢弃，其他会话可继续使用。

主要实现文件：`core/web_lifecycle.py`、`services/conversation_deletion.py`、`infrastructure/web_repository.py`、`adapters/web_app.py`，以及前端 App 和 API。文件发布保护同时接入上传、图片识别、预约图片和附件缓存；没有改写 Agent 的语义策略。

## 实现选择

文件发布与清理使用每个数据库的一把短时可重入锁，使共享物理文件的引用登记与删除具有一致顺序。锁不包含模型或网络调用；不同会话的文件发布可能短暂串行，但普通模型查询无需等待网络级长锁。SQLite 写事务继续提供数据库层面的顺序和回滚。

删除分为 `pending → cleaning → completed`，失败进入 `failed`。明确失败的作业由用户点击重试；不会后台无休止重试无效路径。应用启动后自动恢复 pending／cleaning 作业。

数据库记录与文件系统不具备跨系统原子事务。第一阶段停用后，不再接受该会话的新业务；清理尚未完成时明确显示状态，不声称所有文件已经删除。

## 保留边界

- 已发送给外部接口的请求及费用不能撤回；只阻止其迟到结果写回已删除会话。
- 删除不会影响用户另存文件、既有备份或已被离线浏览器取得的副本，不承诺磁盘级安全擦除。
- 共享公共预约规则缓存保留；其他会话仍引用的物理图片保留。
- 新的文件发布日志用于防止未来未登记文件残留；历史上没有登记且无法确定会话归属的孤立文件，不按猜测归入某会话删除。
- 当前是单机、单 Web 后台实例；未做分布式、多进程跨主机删除协调。
