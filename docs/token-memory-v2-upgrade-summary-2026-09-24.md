# Token 成本、上下文与分层记忆 v2 升级总结

日期：2026-09-24  
项目：`E:\Agent\travel_agent`  
实施依据：[Token 成本、上下文与分层记忆改进方案 v2](token-memory-optimization-plan-2026-09-19.md)

## 1. 交付结论

v2 方案对应的运行时基础、默认关闭能力、配置界面、评测入口和删除／恢复边界已经实现。升级沿用现有单编排器、领域服务、Intent IR、工具 Agent、SQLite、Inbox／Outbox 和版本校验，没有引入通用 Multi-Agent、外部向量数据库或新的跨平台身份关系。

默认发布策略保持保守：

- `AI_BUDGET_TIER=balanced`；
- 用途模型留空时继续使用 `LLM_MODEL_ID`；
- `AI_SUMMARY_ENABLED=false`；
- `AI_VECTOR_ENABLED=false`；
- 日／月 token 限额为 `0`，表示应用不额外限制；
- 未配置真实费率时只展示 token 和“费用未知”；
- 不自动切换正式模型，不自动发送真实会话做付费评测。

阶段 3 的本地检索实验在合成样本中 FTS Recall@5 与混合检索均为 100%，提升为 0 个百分点，未达到 v2 规定的 10 个百分点 Go 门槛。因此混合检索代码保留、可回退，但正式默认继续关闭。

## 2. 阶段 0A：基线与环境

- 按项目 `requirements-web.txt` 和约束文件补齐了 `python-multipart` 等声明依赖。
- 升级前完整后端基线为 678 项通过。
- 离线评测不再读取项目 `.env`；只有 `--live` 模式才加载真实模型配置，避免离线评测接触凭据。
- 当前工作区在实施前已经包含规划方案、研究选源、Web 交互等未提交升级；本轮没有清理、回退或覆盖这些已有改动。

## 3. 阶段 0B：用途级计量、费用与预算

### 3.1 模型调用上下文

新增受控模型调用上下文，记录：

- `purpose`；
- `prompt_version`；
- `context_policy_version`；
- `repair_attempt`；
- `fallback_from`；
- 是否强制使用默认模型。

现有模型调用已标记为意图解析、工具推理、工具回答、行程需求提取、行程生成／修复、研究规划／综合、文档摘要、视觉提取、提醒提取和会话摘要等用途。

### 3.2 数据库计量

`model_calls` 通过增量迁移增加：

- 用途、供应商别名和配置版本；
- Prompt／上下文策略版本；
- 输出上限；
- 缓存输入和推理 token；
- 修复次数和模型回退来源；
- usage 完整性；
- 估算费用、币种和累计标记。

新增 `model_usage_periods`，按日／月、用途和模型累计调用、保守预留、实际 token、估算费用及未知费用数量。该累计表不随普通会话删除而清理，避免删除会话意外释放日／月额度。

### 3.3 成本与硬上限

- 支持应用级日／月 token 预留上限；预留和检查在同一 SQLite 写事务中完成。
- 支持用户配置每百万输入、缓存输入和输出 token 的真实费率及币种。
- 供应商未返回 usage 或费率未知时保持未知，不按零消费计算。
- SDK 内部物理 HTTP 尝试无法确认时，不冒充完整账单。

## 4. 阶段 1A：用途级上下文

新增 `ContextPolicy`，按用途配置总上下文、近期对话、群消息、引用和文档预算，并由经济／均衡／高质量档位调整。

当前用途包括：

- `intent_parse`；
- `plan_reference`；
- `reminder_continue`；
- `travel_lookup`；
- `document_qa`；
- `tool_reasoning`。

简单实时查询不再默认加载旅行文档；文档问答只读取相关片段。对于“文档里写了什么”等泛化文档问题，仍保留带低相关性标记的最新文档回退。引用旧住宿／行程的表达优先使用文档上下文，避免误路由为独立酒店推荐。

## 5. 阶段 1B：调用链去重与用途模型

- Intent IR 新增并校验简单天气、预报、驾车、路况、步行、公交和地点查询操作。
- 已通过 Schema、原文和字段范围校验的简单查询直接调用确定性 `TravelService` 并模板返回，不再进入通用工具 Agent 重复理解。
- 常见问候和致谢绕过语义编译，避免普通闲聊产生无效前置调用。
- 支持意图、摘要、研究和视觉用途模型；未配置时沿用默认模型。
- 小意图模型输出无效时自动用默认模型再解析一次；两次尝试分别计量，最终仍不可靠时保持原有追问／回退行为。

## 6. 阶段 1C／1D：工具可靠性与大型结果

### 6.1 错误分类

`ToolResult` 现在区分临时上游错误、限流、非法参数、权限不足和能力不可用，并携带 `retryable` 与可选 `retry_after_seconds`。未配置、权限和参数错误不再统一标为可重试。

### 6.2 无进展循环检测

Agent 按工具名、标准化参数、状态／错误码、状态版本和结果内容哈希建立执行签名。同一签名跨步骤重复且没有新状态时提前终止；同参数但工具结果已经变化的读取仍可继续。

原有步骤、工具次数、事件调用和 token 预算继续作为硬上限。

### 6.3 Tool Artifact

新增会话隔离的 `tool_artifacts`：

- 大于阈值的只读工具结果全量落库；
- 模型先收到受限片段和 `TA-` 编号；
- 只有实际产生大型结果后才动态暴露 `read_tool_artifact`；
- 支持 cursor 分页读取；
- 平台、会话和用户范围不匹配时拒绝访问；
- 会话删除和留存维护会清理对应 Artifact。

## 7. Prompt Cache 支持

- 将 TravelAgent 稳定身份、安全边界、工具原则和输出协议放到 Prompt 前部；日期、意图、允许工具和任务状态放到动态后部。
- Prompt 和上下文策略使用显式版本。
- 工具 Schema 保持确定性顺序，并继续按任务裁剪。
- 记录供应商实际返回的 cached input 和 reasoning token。
- 未提供缓存 usage 的兼容端点显示“未提供”，不虚构命中率。

是否实际命中、延迟和计价仍取决于当前兼容服务；本项目没有向不支持的端点盲传供应商专有缓存参数。

## 8. 阶段 2：按需会话摘要

新增 `conversation_summaries`、Repository 和 Service：

- 默认关闭；
- 至少 8 个新回合且新增内容达到阈值才生成；
- 每次请求最多生成一次；
- 输出必须引用消息 ID；
- 只总结尚未结构化的结论、否定、纠正和未决问题；
- 不复制正式行程、规划方案、研究报告、提醒、资源编号、权限或长期偏好；
- 最近原文、结构化状态和本轮要求优先；
- 失败继续使用原上下文策略；
- 修改／忘记长期偏好会使已有派生摘要失效；
- 会话删除、留存维护和取消执行遵守现有生命周期。

## 9. 阶段 3：可选本地混合检索

新增默认关闭的 `hash-ngram-256-v1` 本地索引：

- 只索引当前允许范围内的文档分块；
- 使用内容哈希、模型版本和外键管理可重建索引；
- 不下载模型、不调用远程 embedding、不新增独立数据库；
- 与现有 FTS／关键词候选合并；
- 文档删除后通过外键级联清理；
- 关闭时不创建索引表，不影响基础安装。

新增 `scripts/evaluate_retrieval.py` 和合成检索样本。当前评测结果：

| 指标 | 结果 |
| --- | ---: |
| 样本数 | 5 |
| FTS Recall@5 | 100% |
| 混合检索 Recall@5 | 100% |
| 提升 | 0 个百分点 |
| Go／No-go | No-go，保持默认关闭 |

Web“状态与设置”新增：

- 经济／均衡／高质量档位；
- 用途模型；

- 当前日／月保守预留。

模型用量接口不返回提示词、聊天正文、事件 ID 或密钥。

## 11. 删除、留存与兼容性

- 会话删除新增清理会话摘要和 Tool Artifact。
- 删除确认界面显示派生摘要和大型工具结果数量。
- 日／月累计预算独立保留，不随普通会话删除重置。
- 留存维护按事件保留期清理过期摘要、Artifact 和调用明细。
- 旧 `model_calls` 表通过列级增量迁移升级；用途、缓存和费用字段缺失时报告接口可兼容旧结构。
- 未配置用途模型、摘要、混合检索、费率或 token 上限时，保持原有默认模型和核心业务能力。

## 14. 部署与启用

1. 使用 SQLite 一致性备份方式备份当前数据目录，不要只复制正在使用的 WAL 主文件。
2. 安装声明依赖并执行完整测试。
3. 保持 `.env` 中新开关为默认安全值，先重启服务完成数据库增量迁移。
4. 在 Web“状态与设置”确认当前档位、模型和用量信息。
5. 如需用途模型，先只配置 `LLM_INTENT_MODEL_ID`，观察校验失败率、回退率和单位成功任务费用。
6. 只有长会话样本证明净收益后启用 `AI_SUMMARY_ENABLED=true`。
7. 当前检索实验未达到门槛，不建议启用 `AI_VECTOR_ENABLED`。
8. 费率必须填写供应商真实价格；未知时保持空白。
9. 应用 token 上限属于本地保守控制，供应商侧仍需设置账单限额。

## 15. 已知限制

- 本轮没有运行真实付费模型对照，因此没有宣称实际成本下降 20% 或摘要净成本下降 15%。
- Prompt Cache 是否命中取决于当前模型供应商；只记录真实 usage，不保证兼容端点支持。
- 本地哈希 n-gram 索引不是语义 embedding 模型；当前样本无召回收益，因此默认关闭。
- 用途模型回退会产生第二次调用；是否节省费用必须以单位成功任务总费用判断。
- 当前全局 Python 环境中的 `streamlit 1.45.1` 要求 Pillow `<12`，而项目约束使用 Pillow `12.2.0`；该冲突属于共享环境中的项目外依赖，建议使用独立虚拟环境运行旅行 Agent。
- 当前工作区仍包含本轮开始前的未提交升级；本轮没有创建提交或发布远程代码。
