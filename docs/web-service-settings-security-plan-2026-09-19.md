## 1. 建议结论

可在本地网页增加“设置 → 服务配置”，输入搜索服务、模型服务及高德 Key，由后端保存到固定的 `E:\Agent\travel_agent\.env`。用户无需手工编辑文件。

这个入口属于**程序服务配置**，不属于聊天、长期记忆或 skill。Agent 没有读取原始密钥、修改配置或导出 `.env` 的工具。用户只需在专用表单输入，不应把密钥发到聊天窗口。

采用“密钥只写入、不回显；字段白名单；原子保存；重启生效；提交前检查”的首版。`.env` 是本机明文文件，Git 忽略不等于加密或权限控制；防止误提交可以建立多层措施，但无法保证恶意本机程序、用户主动强制提交或手动上传压缩包时绝不泄漏。

## 3. 页面交互

### 3.1 第一版字段

| 配置组 | 字段 | 交互 |
| --- | --- | --- |
| 搜索 | 供应商、API Key；适配器确有需要时才提供服务 URL | 内置已选择供应商地址，减少填错及误把 Key 发给错误站点 |
| 模型 | API Key、Base URL、模型 ID | URL 作为敏感配置管理；保存时核验地址格式和端点绑定 |
| 高德 | Web 服务 Key | 固定官方服务地址，无任意 URL 配置 |

搜索变量名待供应商选定后确定；模型和高德沿用 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL_ID`、`AMAP_API_KEY`。

首版不提供任意环境变量编辑器。不开放 QQ Token、监听地址、文件路径、代理变量、数据库目录、开发模式或系统环境的修改，以免网页配置成为文件写入或网络权限入口。

### 3.2 密钥显示及提交语义

- 密钥框初始为空，旁边显示“未配置 / 已配置 / 由启动环境提供”，不返回旧密钥，默认也不返回前几位或后几位。
- 可临时显示用户本次正在输入的新值；不能通过“眼睛”按钮取回已存密钥。
- 字段省略或未输入表示保留原值；替换必须提交新值；删除用单独“清除本地配置”操作，不以空白字符串猜测删除意图。
- 成功后清空表单中的密钥，仅展示配置状态、配置版本、保存时间及是否需要重启。不保存表单草稿到 localStorage、sessionStorage、IndexedDB 或聊天记录。
- 请求失败时只保留当前页面内必要输入，允许用户重试或清空；不在错误对象、浏览器日志或分析埋点中复制输入值。无法承诺 JavaScript 内存可被立即物理擦除。
- Base URL 必须不含用户名/密码、查询参数或 fragment，禁止把 Key 放进 URL。仅显示通过校验的地址；它不会传给模型、研究报告或普通诊断导出。

页面注明：“此配置保存到本机项目 `.env`。模型和地图配置也可能影响同项目 QQ 服务下次启动。”

### 3.3 保存与连接测试分开

“保存”只做本地校验和落盘，不自动向供应商发送 Key。可另设“测试连接”，在按钮旁展示目标主机和预计执行的固定检查；点击即授权这一次检查，不再弹出重复的笼统确认。

测试由后端执行，超时/响应体受限；不发送聊天、文件、用户偏好或整个 `.env`。尽量采用服务提供的低成本验证接口；若只能调用模型完成极短测试，应提示可能有少量费用。测试成功不代表模型一定支持所有工具调用和图片能力。

服务端仅返回有限状态（成功、凭据无效、限流、超时、网络不可达、模型不可用），不把 SDK 原始异常、请求头、完整 URL、供应商响应体直接返回页面。

## 4. 凭据与端点绑定

自定义 Base URL 具有安全含义：密钥会发送给该主机，不能因为字段名称为“URL”就当普通文本处理。

- 搜索供应商的正式端点和高德端点由适配器定义；首版不开放任意搜索代理。
- 模型自定义远端地址限定 HTTPS 公网端点，验证 DNS/连接目标；禁止用户信息、查询参数和跳转转发认证头。对 loopback、局域网及元数据目标默认拒绝。若以后接入本地模型服务，应单独设计显式 loopback 模式，不混用远端供应商密钥。
- 修改 Base URL 或供应商时，已存 Key 不能自动跟随到新地址；须重新输入用于该端点的 Key。仅修改模型 ID 不必重新输入。
- “测试已保存配置”只能使用该服务当前绑定的端点；不得出现 `test(url=任意地址, use_saved_key=true)` 这样的接口。
- 测试请求不跟随重定向，不关闭 TLS 证书验证；网络库代理环境的行为需显式确定，不能悄悄经不明代理发送凭据。

保存的新配置必须满足这些约束。既有手工配置若超出本轮允许范围，应显示“不支持网页编辑/测试此配置”，不能静默改写原有合法使用场景或悄悄发送旧 Key。

## 5. 后端存储设计

新增小型 `LocalServiceSettings` 存储服务，负责字段映射、来源解析、版本、校验、脱敏和 `.env` 写入；适配器负责 HTTP，不能把配置写入交给 LLM 或通用文件工具。

建议接口：

```text
GET   /api/settings/services       返回安全状态、可编辑的非密钥配置、opaque version
PATCH /api/settings/services       字段级保留/替换/删除，带 expected_version
POST  /api/settings/services/test  固定服务类型及受约束配置，返回规范化状态
```

不得提供读取完整 `.env`、密钥明文或配置文件下载接口。配置版本应是不含明文的随机标识或服务端不可逆受密钥保护的标识；不公开整个文件或低熵值的可枚举哈希。

### 5.1 固定路径与安全序列化

- 固定写项目根目录 `.env`，不接受客户端提供路径，不写父目录回退文件；拒绝意外符号链接、目录联接或其他重解析目标。部署目录应由当前用户控制，不把本机恶意进程防护寄托在一次路径检查上。
- 只修改白名单字段，保留无关配置和注释。若检测到相关键重复、文件格式无法可靠解析，返回不包含原值的错误并保留原文件，不选择一个重复值继续写。
- 拒绝 CR、LF、NUL、控制字符和超长输入；使用经过验证的 dotenv 序列化方式，不手工拼接未经转义的 `KEY=value`。
- 覆盖引号、反斜杠、`#`、空格、`$` 和 `${...}` 的往返测试。保留现有加载方式时，对于不能保证原样加载的插值语法明确拒绝；不能默默把 Key 展开成其他环境变量。
- 不执行输入，不通过 shell、命令行参数或 `setx` 保存配置；不把整个 `.env` 装载结果导出为子进程通用环境副本。

### 5.2 原子写入和并发

1. 验证访问、CSRF、请求体和字段白名单。
2. 取得项目配置写锁，检查 `expected_version` 及实际文件是否被外部编辑。
3. 在内存生成合并结果，用同一 dotenv 解析规则校验预期值。
4. 在同目录创建唯一临时文件，设置受限权限后写入、flush/fsync；用原子替换更新目标，再核验结果。
5. 成功返回状态，异常保留旧文件并删除本次临时文件；进程崩溃后的残留只清理本功能可识别的临时文件，不通配删除其他 `.env` 文件。

不默认生成 `.env.bak`，减少凭据副本；原子替换并不等于历史版本备份。如未来提供备份，必须明确它也包含明文密钥并采用相同保护。

Web 已有的数据目录锁不足以保护项目 `.env`：不同数据目录的实例仍可能编辑同一文件。需要按目标配置文件加跨进程锁。外部编辑器不一定遵守锁，应在最终写前重新检查版本并提示冲突；不能保证与任意恶意写进程完全互斥。

### 5.3 文件权限

Linux/macOS 使用只允许服务用户读写的权限，并保护临时文件；Windows 使用用户/服务身份相应的 NTFS ACL，不能把 `chmod(600)` 当作 Windows 已完成隔离。替换文件时必须维持受限 ACL，不能因新临时文件继承宽权限而放开访问。

若无法建立本功能要求的权限，应不保存新凭据，返回不包含值的说明。只调整配置文件及其临时文件，不递归修改整个项目权限。磁盘加密/系统凭据库可作为以后增强，但 `.env` 仍按用户要求是明文配置，本轮不宣称加密落盘。

## 6. 生效方式、优先级与跨端影响

首版明确采用**保存后重启生效**。当前运行时已创建模型/地图客户端，简单写 `.env` 或 `os.environ` 不会安全替换所有服务；热更新还涉及在途任务、后台调度和连接关闭，不应混入首版。

页面区分“已保存配置”和“本次运行配置”，提示哪些项目待重启。由用户在终端停止并重新启动 `python run_web.py`，不执行来自网页的 shell 重启命令。需要使用新配置的 QQ 进程也要单独重启；重启前它沿用原配置。

保留加载优先级：启动环境 > 项目 `.env` > 父目录回退。服务端需在 dotenv 加载前记录来源，不能看到 `os.environ` 有值就一概标“由系统环境提供”。

- 启动环境控制的字段在网页设为只读，提示需修改启动环境，避免“保存成功却永远不生效”。
- 父目录回退的字段可通过写项目 `.env` 显式覆盖，但不能编辑父目录文件。
- 删除本地配置时显示后果：删除键可能重新启用父目录回退。“禁用此服务”应以服务开关或明确空值覆盖表达，不能让用户以为已经停用却继续使用旧凭据。
- Docker 环境变量和 Compose `env_file` 通常在容器创建时注入；在容器里写 `.env` 未必持久或生效。本轮设置功能以本机运行支持为验收范围，容器需将固定配置文件安全挂载并确定启动优先级后才启用写入。

本轮仍按项目级服务配置处理，Web 与 QQ 的对话和偏好隔离不等于服务凭据隔离。如果以后要求两端使用不同 Key，可再拆分受保护的 Web 配置文件，不在本轮暗改既有 QQ 读取行为。

## 7. Web 访问与日志保护

复用并为新接口单独测试：仅 loopback 监听、精确 Host/Origin、Cookie 会话、CSRF、拒绝跨站、CSP、防嵌入和 `Cache-Control: no-store`。秘密只放 POST/PATCH 请求体，不放 URL、Cookie 或前端打包变量。

特别注意：FastAPI/Pydantic 默认校验错误可能包含无效的 `input`。密钥接口必须定制错误响应，只返回字段名和固定错误码，禁止把原始输入、异常上下文或 traceback 串进 422/500 响应。

敏感路由不记录请求/响应正文；服务测试不得启用 HTTPX/OpenAI/requests 的敏感调试日志。审计只记服务类型、被修改的字段名、时间、结果和配置版本。诊断包、评测 artifact、研究报告和模型用量表都不能包含密钥或原 `.env`。任何脱敏过滤都是补充，主策略是根本不记录。

前端禁止 `VITE_*` 暴露密钥，禁止把 `.env` 拷进 `frontend/public`、dist、source map、导出文件或站内通知。页面自身及被展示的网页片段都不能执行外部脚本。

本地 bootstrap 不是真正管理员认证。同一电脑上能访问服务的其他进程/使用者仍可能进入设置，本方案不声称防住本机恶意程序或恶意浏览器扩展。若要给多人或局域网使用，必须先做认证和配置管理员权限；不是把监听改为 `0.0.0.0` 就可以发布。

## 8. 防止上传 GitHub 的多层措施

### 8.1 忽略规则与构建边界

实施时补齐 `.gitignore`：`.env`、`.env.*`、本功能临时配置文件；仅放行人工维护且无真实值的 `.env.example`。按实际文件命名覆盖轮转日志（例如 `botpy.log.日期`）、生成的诊断包等，避免以为 `*.log` 能覆盖所有日志。规则过宽时应保留必要测试 fixture，不靠删除用户文件来“修复”泄漏风险。

增加 `.dockerignore`，排除 `.env` 及其变体、Git 元数据、运行数据和诊断日志；必要占位模板按明确规则保留。`.gitignore` 不控制 Docker 上下文、手动 ZIP、网盘同步或上传附件；发布包必须采用受控文件清单。

### 8.2 已跟踪文件与历史

保存前检查目标 `.env` 是否已经被 Git 跟踪以及预期忽略规则是否生效。若已跟踪，拒绝从 Web 写入新的密钥并给出文件路径级说明；先由项目维护流程解除跟踪，再恢复保存。不要自动重写 Git 历史或偷偷删除版本库中的文件。

`.gitignore` 对已跟踪文件无效，也无法清理过去的提交。若确认真实 Key 曾公开，优先到供应商吊销/轮换，再处理历史；仅删除当前文件并不足够。本次只做了有限路径级历史检查，未宣称已扫描所有既有日志、压缩包或远端历史。

### 8.3 提交前阻断与 CI

增加本地暂存区检查和可安装的 pre-commit/pre-push hook：

- 阻止提交非模板 `.env`、本功能临时文件及已识别的含秘密文件。
- 对新增暂存内容做通用 secret 扫描；在本机可追加对已知实际 Key 的完整值匹配，所有处理留在本机且只输出文件路径、规则和状态，不输出匹配行或匹配值。
- 模板仅可包含占位符；未知格式 Key 的检测不可能百分之百准确，不把扫描器当成唯一保护。
- CI 加入脱敏的秘密扫描和打包内容检查；固定扫描工具版本，不将原值写入 CI 日志/artifact。

本地 hook 需要安装，Git 默认不会自动执行仓库里的 hook，用户也能用 `--no-verify` 绕过；文档必须说明。CI 在推送后运行，只能阻止后续合并/发布，不能保证秘密从未到达远端。平台的 Secret Scanning/Push Protection 在可用时作为额外防线，不假设当前账号已开启。

## 9. 必须通过的验收

所有测试使用独立临时目录和可识别的假 Key，不覆盖用户正式 `.env`。

| 场景 | 验收结果 |
| --- | --- |
| 新建/更新 Key | 保存正确，GET/保存回执/页面刷新均不返回旧值 |
| 留空/清除/替换 | 留空保留；显式清除可追踪；删除回退与停用含义正确 |
| 特殊字符与非法值 | 允许值原样往返；换行/插值/未知字段不能注入其他变量 |
| Pydantic、SDK 和网络异常 | 422、500、日志和浏览器错误不包含假 Key、认证头或秘密 URL |
| 保存故障/磁盘权限/并发编辑 | 原文件不损坏；旧值不被部分覆盖；权限无放宽；冲突可见 |
| 改供应商或 URL | 不可携带旧 Key 到新地址；认证请求不随重定向；内网目标被拒绝 |
| 恶意跨站、失效会话、缺 CSRF | 设置及测试接口拒绝请求，文件不变 |
| 前端持久化与构建 | 假 Key 不出现在 storage、dist、source map、导出或模型上下文 |
| 临时 Git 仓库 | 普通 add 忽略秘密文件；被强制暂存时检查阻断；已跟踪目标拒绝网页保存；占位模板可正常提交 |
| 配置来源 | 继承环境/项目/父目录来源正确，重启前后生效状态明确 |
| QQ/Web 共用 | 不误标为 Web 私有设置，不重启或篡改另一个正在运行的进程 |
| 完整回归 | 现有聊天、文件、删除流程、行程、提醒和双端入口保持通过 |

连接测试先用本机测试服务器/网络替身模拟各种错误和跳转，不把真实密钥发给测试地址。真实供应商只针对用户配置并明确点击测试的端点做有限检查，结果分开报告。

## 10. 审核后的实施位置

在主方案增加 S0.5：先实现本地服务配置和防泄漏验证，再接搜索供应商与研究功能。建议分工边界：

- `core/local_service_settings.py`：配置字段、来源与不可回显状态。
- `infrastructure/env_settings_store.py`：解析、版本、锁、权限和原子写入。
- `adapters/web_app.py`：受保护设置/测试接口及脱敏错误响应。
- `frontend/src/`：服务配置表单，不复用聊天输入或草稿持久化。
- `.gitignore`、`.dockerignore`、提交检查脚本及 CI：误上传和打包防线。
- 新配置专项测试：临时文件、Git 仓库、异常返回和构建产物扫描。

按当前本地单使用者模式实施；不增加一套多账号系统，不把密钥保存为用户偏好。本轮审核重点是：接受项目级明文 `.env`、网页只写不回显、保存后重启，以及上述防误上传措施和明确边界。
