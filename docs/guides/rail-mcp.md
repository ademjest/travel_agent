# 铁路 Remote MCP、车次查询与行程交通

支持自然语言单向/往返查询、任务续接，以及行程中的往返交通、席别和首末日可用时段约束。铁路为可选能力，配置后启用。

在服务设置的“铁路查询”填写完整 `RAIL_MCP_CONFIG` JSON：

```json
{"enabled":true,"transport":"sse","endpoint":"https://example.com/private/sse","timeout_seconds":20}
```

必须替换为部署方实际给出的完整地址；支持 `sse` 与 `streamable_http`。可选 `bearer_token` 用于实际需要 Bearer 鉴权的服务。不猜路径、不自动切换传输、不启动本地 Node 服务。时间必须带时区；没有可靠有效期时可以省略 `expires_at`。过期、鉴权失败和工具合同不兼容不会自动续期或绕过校验。

专属地址和鉴权按凭据整体保存，不回显。留空保留、完整替换、清除三种操作沿用现有设置规则；更换地址时需重新提供完整鉴权。保存在本机 `.env`，重启后生效；不要把实际配置提交到 Git。

“测试铁路连接与工具合同”仅初始化和发现允许工具，不查询车票；一键服务测试中的铁路项执行相同的连接与合同检查。连接成功只说明合同兼容，不代表余票准确或查询覆盖全面。真实业务验收使用现有 evaluation 入口，单独明确工具调用额度，不消耗模型 tokens：

```powershell
python scripts/run_evaluations.py rail_mcp --output .upgrade-testing/rail-fake.json
python scripts/run_evaluations.py rail_mcp --replay tests/fixtures/rail_mcp_2026-10-27.json --output .upgrade-testing/rail-replay.json
python scripts/run_evaluations.py --mode live_provider rail_mcp --date 2026-10-30 --max-calls 12 --max-connections 1 --seconds 120 --output .upgrade-testing/rail-live.json
```

真实模式从已注入的环境变量读取配置，不自行读取或改写生产 `.env`。使用新的输出路径保留原始证据。每次单段查询通常提交三次 tools/call：两端代码解析和一次车票查询。仅当收到明确的 `isError=true` 失败回执时，该步骤用完全相同参数最多再试一次；最坏共六次，仍受整组调用额度约束。超时、断线或响应格式异常不自动重发车票请求。这里的 tools_call 是进入 SDK 调用的保守尝试计数，不保证等于供应商收到的物理请求数；远端内部 HTTP 次数和费用未知。

运行时复用所属事件循环中的单个会话任务。请求超时与 SSE 空闲读取分开，SSE 空闲上限为 300 秒；连接空闲达到请求超时时间后，下次使用先通过同一会话任务发协议 ping 检查，失败时在提交业务请求前恢复连接。并发查询共享恢复过程，不定时向供应商发送心跳或无限后台重连。

线上客户端每 60 秒最多尝试连接两次，达到上限后由稍后的新查询再次触发；评测显式传入的 `max_connections` 另作整个客户端生命周期的硬上限，不因冷却而重置。ping 独立计入 `operations.pings`，不算车票工具调用。正在执行、结果未知的请求不会因重连自动重发；关闭客户端后也不会由新请求重新启动。失败或过期仅影响铁路能力，既有 Web、QQ、历史记录和其他工具继续可用。

具体车站按返回站码严格过滤，同城其他站不会当作指定车站。每次仅获取请求时段的候选，候选上限固定为 100 条，与文本摘要和网页每页显示数量分开；达到上限时明确结果可能不完整，不声称全天无车。城市请求保留城市范围和真实车站，供应商城市覆盖完整性尚未独立验证。车票不是订单；余票随时变化，未获取的价格/余票保持未知，跨午夜按请求的乘车日期计算。上游报告版本与 schema 指纹留在回执中，不能据此宣称已锁住托管端实现。

## 自然语言车次查询

### Web 车次卡片

车次卡片每页显示 6 组。相同乘车日的同一车次分组展示，不同起终站、出发时间和区间票价/余票作为独立选项保留，可展开查看。本次取得的组数、实际出发时间范围和数据时间会明确展示。

用户只查上午时，仅查询 09:00–12:00 并分页展示上午结果。“全天”查询可在同一快照内筛选上午、下午和晚上；分页、筛选和展开不调用模型或铁路接口，不刷新数据时间。未查询的时段不会伪装成本地筛选。

“查询下午”“查询晚上”“扩展查询全天”“刷新余票”属于明确的新查询操作：保留日期、站点范围和车种，只改变所选出发时段，通过同一铁路业务入口获取新数据，生成新的聊天结果卡片，不调用意图模型。达到供应商候选上限时，卡片提示结果可能不完整；可缩小时段补查。

历史回复若保存了成功 RPC 及相同的原始数据时间，可在本地恢复完整列表。无法恢复的旧记录会注明只保存了部分结果，需重新查询，不假装完整。

Web 中可点击铁路结果或补充问题旁的“引用查询”，在输入框上方确认引用摘要后输入更正。首版支持具有可恢复铁路记录的助手回复；多条查询并存时可明确选择一条，原用户请求通过对应回复选择。取消引用不会发起查询。

引用使用该条消息当时的查询条件，发送后创建新只读任务并重新获取实时车票，不采用同一旧任务后来修改的条件或旧余票。即使旧任务超过自动续接的 30 分钟有效期，历史快照仍可引用；消息或快照被清理后需重新提供条件。未引用且存在多条候选时，仍需选择查询对象。已有行程/提醒等写操作的确认规则不变。

历史“明天”等相对日期固定为当时对应的实际日期；本轮明确说“改成明天”时按本轮北京时间重新解析。只有“晚一点/早一点”等模糊更正时，旧时段失效，系统只追问新的明确时段。引用往返结果但未说明要改哪一段时仍需补充方向。

启用铁路与模型后，可在 Web 输入“明天武汉到南京怎么坐车”。明确城市和日期即可，缺少日期时会只追问日期，不默认今天。具体站点、出发时段和车次偏好按本轮要求保存；无高德 Key 也能查询铁路。

- “10月30日武汉站到南京南，上午出发，只坐高铁”：保留具体站、仅 G 字头、上午时段。
- “改成后天，晚一点出发”：唯一铁路任务会保留两端并更新日期；“晚一点”仍需补充明确时段。存在多个候选任务时会要求确认所指。
- “南京南到夫子庙坐地铁怎么走”仍查询市内交通；明确自驾仍使用驾车能力；当前不提供实时机票查询。

未指定车种时默认高铁优先；仅当返回候选中 G 字头不足时列出明确标注的 D 动车备选。明确只坐高铁时不会以动车替代。每次只查询所要求方向，明确往返并提供两个日期时才查两段；查询不创建行程、提醒或订单。

日期与时段按北京时间解析。早上按 06:00–10:00、上午 09:00–12:00、下午 12:00–18:00、晚上 18:00–24:00 筛选；“全天”“整天”“一整天”“不限时间/时段”“时间不限”按乘车日 00:00–24:00 查询，也支持“全天都可以”“整天都行”等表达。已有上午等条件时，“改成整天”会覆盖旧时段，保留日期、两端与车种。全天只取消出发时段限制，不代表不限车种，也不表示列出所有车次。可直接提供“09:00至11:30”等范围；含糊时段或“全天但上午不行”等尚未可靠解析的限定仍需明确。

同一事件的相同工具请求复用结果与原始数据时间；新请求重新查询。远端解析与车票提交逐步保存检查点，成功步骤不重做；明确失败及一次重试分别保存回执，重放不重复消费已完成的步骤。只有客户端能确认尚未进入 SDK 提交的失败才释放该次预留；已提交但没有确认回执时不会自动重发。错误结果保留具体工具名与受限重试次数，服务日志只记录错误分类、异常类型和协议码，不输出凭据或供应商正文。城市覆盖完整性、未提供的票价和余票均保留限制。

新事件冻结 legacy-v2（可选 compact-v2）目录；已冻结或旧的未版本化事件仍沿用旧目录，不能自动获得新增铁路动作。

默认离线验收：`python scripts/run_evaluations.py rail_query --output .upgrade-testing/rail-query-fake.json`。真实模式必须先明确模型和 MCP 额度，通过现有 evaluation runner 绑定持久预算，禁止重置旧账本来扩大额度。

## 行程中的去程与返程（U4）

新完整行程在明确跨城出发地和日期后，会经同一铁路查询入口安排有限候选；默认往返、高铁优先，并说明默认来源。城市公交/步行与城际方式分别处理。已在目的地、明确单程/自驾/飞机或已有车票时按声明处理；缺出发地和某个周末等未定日期只保留城市参考并提示待补，不拿系统暂定日期查票。

可询问“我从武汉出发，11月3日去南京两天，含来回，市内公交，不夜游”。回复和侧栏按去程、游览、返程展示。首尾日受车站时间、接驳和缓冲约束；没有完整时段时可以是交通日。当前活动仍按上午/下午/晚上安排，不代表已逐分钟核验营业和预约场次。

窗口默认出站缓冲30分钟、进站缓冲60分钟；接驳未取得时暂按60分钟参考。这些是可核对的规划假设，不是铁路官方保证。目的地玩满N天会保留该口径；需要额外交通日时，预览会列明，出/返程日期不足仍需补充。

明确变更返程、出发地或日期会生成新草稿。候选中已保存的指定车次可复用，查不到时提示刷新/补充；无关餐饮修改复用交通快照。确认只提交当前预览，不暗中重查车票或换车；冲突草稿不能直接确认。可用“刷新行程交通”显式获取新交通资料。

票价标单人/单程与席别，未核算确定的家庭总价；未知费用不按0计入。余票可能变化，推荐或确认行程均不代表已购票、已出票或锁票。旧行程只读查看不触发新查票。


铁路时段统一口径：早上/早晨06:00–10:00，上午09:00–12:00，下午12:00–18:00，晚上/晚间18:00–24:00。支持13点到18点、13至18点及分钟范围；起点包含、终点不包含。旧查询按保存的规范窗口读取，新查询按本口径执行。
