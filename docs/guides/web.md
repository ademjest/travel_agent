# 彼岸 · 本地网页版使用说明

[返回项目总览](../../README.md) · [使用指南目录](README.md) · [QQ 使用指南](qq.md)

## 1. 启动

网页版使用现有 Agent 与旅行工具，QQ 离线时也可独立工作。默认打开 `http://127.0.0.1:8080`。

首次准备，在项目目录使用 Python 3.11 环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-web.txt -c constraints-py311.txt
cd frontend
npm ci
npm run build
cd ..
python run_web.py
```

若已有 Conda `agent` 环境，可以使用 `conda activate agent` 代替上面的环境创建与激活。Linux/macOS 使用 `source .venv/bin/activate` 激活。首次使用可先将根目录 `.env.example` 复制为 `.env`，填入真实配置，或启动后使用左侧“服务配置”。

前端构建使用 Node.js 24。项目升级前端代码后重新执行 `npm ci` 和 `npm run build`；日常运行不用启动 Node 或 Vite。

以后只需执行 `python run_web.py`。也可以双击项目内 `start-web.cmd`：优先采用 `WEB_PYTHON` 指定的解释器；否则检查当前 Python 的依赖；当前环境不足时，尝试已存在的 Conda `agent` 环境。脚本不会自动安装包或修改系统配置。

若希望明确指定 Python：

```powershell
$env:WEB_PYTHON = '你的Python环境完整路径\python.exe'
.\start-web.cmd
```

关闭启动终端或按 Ctrl+C 停止服务；网页关闭不会停止后端。再次启动会恢复同一数据目录中的记录。

## 2. 配置

默认优先使用进程环境变量，其次项目 `.env`，最后兼容父目录 `.env` 中未设置的值。网页左侧“服务配置”会将你明确保存的修改合并到**项目根目录 `.env`**；模型 Key、模型地址、模型名称和高德 Key 都可以替换，已有密钥不回显到前端。

若被修改的字段来自启动环境，保存时会在项目 `.env` 的 `WEB_SETTINGS_OVERRIDE_KEYS` 中记录该字段名称，Web 重启后优先使用该字段的项目配置。未修改的环境配置继续生效；父目录文件和系统环境不会被修改。此覆盖规则只用于 Web 启动，不改变 QQ 的环境变量优先级。清除密钥后，已标记的字段保持空值，不再回退旧的环境密钥。

替换模型地址时需要同时输入用于新地址的模型 Key。保存后重启后端生效，字段旁会显示“等待重启”。如果仍看到旧版只读输入框，请重启后端并刷新网页；前端源代码更新后需要重新执行 `npm run build`。左侧“本地空间状态”只展示后台健康状态，“偏好设置”只管理明确保存的长期默认。

点击“一键测试全部服务”可检查已保存的默认模型、用途模型、Tavily 搜索和高德天气 API。相同文本模型合并测试一次；视觉模型使用固定测试图片额外验证图片输入。结果在蓝紫色浮层中逐项显示通过、失败、跳过及耗时，未配置的项目自动跳过。完成后 20 秒自动关闭，鼠标悬停或键盘聚焦可暂停，也可点击右上角 × 手动关闭。关闭浮层只隐藏结果，不取消已发出的请求。

请先保存修改再测试。测试会发起小型实际推理、搜索和天气查询，可能产生少量费用或消耗额度；不会发送聊天内容和用户附件。模型测试用量记录在 `service_probe` 分类中。已保存配置即使尚未重启也可测试，但 Agent 仍需重启后使用新配置。单独的“测试已保存模型地址”只检查 `/models`，并不验证推理或图片能力；一键测试通过也不代表所有工具调用、JSON 输出或地图 API 权限均已验证。

| 配置 | 作用 |
| --- | --- |
| `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL_ID` | 原有模型配置，支持工具调用和图片输入的接口 |
| `LLM_INTENT_MODEL_ID`、`LLM_SUMMARY_MODEL_ID`、`LLM_RESEARCH_MODEL_ID`、`LLM_VISION_MODEL_ID` | 可选用途模型；留空继续使用 `LLM_MODEL_ID`，意图模型校验失败会回退默认模型 |
| `AI_BUDGET_TIER` | `economy`、`balanced` 或 `quality`；默认 `balanced`，控制用途级上下文和输出上限 |
| `AI_DAILY_TOKEN_LIMIT`、`AI_MONTHLY_TOKEN_LIMIT` | 应用级保守 token 预留上限；`0` 表示不设置，供应商侧账单限额仍应单独配置 |
| `AI_SUMMARY_ENABLED` | 默认 `false`；启用后仅在长会话达到阈值时生成带来源引用的派生摘要 |
| `AI_VECTOR_ENABLED` | 默认 `false`；启用本地BGE语义与关键词混合检索，需先准备模型和可选依赖；当前仍属实验能力 |
| `AI_EMBEDDING_MODEL_DIR` | 本地BGE模型文件夹，相对路径以项目目录为准，例如 `.models/bge-small-zh-v1.5-onnx` |
| `AI_EMBEDDING_MIN_SIMILARITY` | 语义召回门槛，0到1；0.5来自当前小型开发集，不保证适合所有资料 |
| `LLM_INPUT_PRICE_PER_M`、`LLM_CACHED_INPUT_PRICE_PER_M`、`LLM_OUTPUT_PRICE_PER_M`、`LLM_PRICE_CURRENCY` | 可选真实费率，用于本地估算；币种默认 USD；历史 usage 可按当前费率回算，真正未知部分不按零消费计算 |
| `AMAP_API_KEY` | 高德 Web 服务类型 Key，用于地点、天气与路线 |
| `SEARCH_API_KEY` | Tavily 搜索 Key，联网搜索攻略时需要；公开页面读取单独处理 |
| `TRAVEL_SEMANTIC_MODE` | 日常使用设置为 `execute`；`shadow` 只记录解析，`preview` 不执行语义写操作 |
| `WEB_HOST` | 默认 `127.0.0.1`，当前只允许本机回环地址 |
| `WEB_PORT` | 默认 `8080`，可避开端口冲突 |
| `WEB_DATA_DIR` | 默认 `data/web`，相对项目根目录解析 |
| `WEB_OPEN_BROWSER` | 是否在启动后打开浏览器；设为 `false` 可关闭 |
| `WEB_DEV` | 仅前端开发时设为 `true`，允许本机 5173 端口代理访问 |

无需 QQ AppID、OneBot token 或 NapCat。缺少外部接口配置时页面仍可以打开，但相关业务会提示不可用。“已配置”只表示字段完整，实际连通性需通过查询验证。

每个数据目录只允许一个 Web 后台实例，避免多个调度器重复运行。若端口已占用，请访问已有网页或改用其他端口；不要重复启动同一数据目录。

## 3. 交互

- 点击“开启新对话”，或在欢迎页直接输入问题。快捷示例先填入输入框，可以编辑后发送。
- Enter 发送，Shift+Enter 换行；中文输入法选字不会误发消息。
- 通过附件按钮、拖放或粘贴图片添加资料。支持 TXT、Markdown、DOCX、XLSX、JPEG、PNG、WebP；每个文件最多 5 MB，每条消息最多 8 个附件。图片和文档分开发送。
- 附件“已上传”表示保存到本地，发送后才开始导入或识别。查看右栏“资料”确认文档已导入。
- 右栏展示当前会话中保存的行程、提醒、预约计划、定时查询和规则监测。窄屏下使用右上角按钮展开。
- 行程和规则产生待确认变更时，核对预览后点击确认；确认绑定具体版本，旧预览不会静默覆盖新版本。未支持结构化卡片的预约流程仍可按回复中的明确命令确认。
- “调整这一天”“取消这条提醒”等快捷操作先填入输入框，核对并发送后执行。
- 任务执行中可以请求取消。已经完成的业务操作不会回滚；已设置提醒应单独取消。
- 失败重发保留相同请求编号以避免重复接收；要修改内容后重新提交时会生成新编号。
- 刷新网页后能恢复已提交消息和任务。未发送文字草稿保存在当前浏览器；未发送附件不保证跨刷新恢复。
- 回复支持数学公式排版：行内使用 `$E=BLv$` 或 `\(E=BLv\)`，独立公式使用 `$$` 或 `\[...\]`。独立成行的 `[`、LaTeX 正文、`]` 也会兼容渲染；代码示例保持原样，长公式可横向滚动。历史消息刷新后同样适用。
- 每个聊天窗口顶部显示“本会话用量”，汇总当前会话的 token 和估算费用；点击展开可查看输入、缓存输入、输出、推理 token，以及按用途/模型的调用明细。随消息自动刷新，切换会话后显示对应窗口的统计。总 token 为输入加输出，缓存输入和推理 token 不重复累加；统计只读取本地保留的模型调用记录，不产生额外模型费用。

可直接尝试：

```text
查询天气 武汉
武汉站到湖北省博物馆坐地铁怎么走？
帮我规划2026年10月18日开始的武汉2天行程，使用公共交通，必去湖北省博物馆。
第二天改为室内
1分钟后提醒我带身份证
查看我的提醒
1分钟后告诉我武汉当前天气
查看定时查询
监测湖北省博物馆预约规则，到2026年10月1日
查看规则监测
```

示例日期仅用于说明，请按实际出行时间调整。模型结果和数据源可能需要澄清；没有真实来源的数据不会因为换成网页而获得保证。

## 4. 联网攻略、行程与偏好

左下角现在分为三个独立入口：“本地空间状态”查看后台任务，“服务配置”管理模型、地图、搜索、预算和用量，“偏好设置”管理长期旅行默认。服务字段按联网搜索、模型基础配置、用途模型、预算与记忆、费用估算分组，并提供用途和填写示例。密钥框留空表示保留原值，清除需单独操作；“已配置”并不保证接口额度或模型能力可用。搜索使用 Tavily 官方接口，不支持任意搜索供应商地址。

推荐体验顺序：

```text
帮我搜索武汉三日游攻略
根据研究结果规划行程，10月1日到10月3日
我喜欢轻松一点的行程，然后不太喜欢打车，尽量步行或者公交地铁出行
确认行程修改
查看行程
```

根据实际出行时间替换示例日期。研究结果附来源与检索时间，只用于当前会话；公开页面内容是参考资料，不是执行操作的授权。搜索失败、来源不可读或预约规则不足时会明确说明。

搜索前会自动读取项目内的 [旅行攻略选源 skill](../../skills/travel-research/SKILL.md)。国内攻略优先小红书、知乎及马蜂窝、携程等中文平台；国外目的地优先国际旅游平台和当地官方信息。可以明确说“搜索京都攻略，只看小红书”或“搜索武汉攻略，不要小红书”，指定平台优先于默认地域策略。目的地分类需要已配置的模型；无法可靠解析平台限制时会说明原因。

来源不足或公开正文不可读时，会在未严格限定平台的前提下补充其他公开结果。登录、验证码和动态页面可能只能得到搜索摘要；引用会区分“已读正文”“仅搜索摘要”“读取失败”。每次研究最多四次基础搜索，通常为两到三次，因此可能比原来的单次搜索使用更多搜索额度。

返回 HTTP 200 并不保证取得攻略：页面不存在、访问验证、仅含导航和公司页脚的内容会被过滤。定向搜索可找到链接，但无法保证目标平台的任意笔记都能公开读取。

调整 `skills/travel-research/SKILL.md` 的选源指引及同目录 `sources.json` 的站点分组，可影响下一次新搜索；进行中的请求保留原搜索计划以便断点恢复。新增 skill 不会自动获得平台 API 权限或绕过登录。首次更新这次后端代码后，需要重启服务。

探索性规划和联网研究会作为“方案草稿”保存在当前会话。右侧“方案”标签可查看、采用或删除草稿；它与正式行程分开。可以说“采用最开始的方案”“采用刚才搜索的四日方案”或“查看方案草稿”。一份方案有多种天数时，系统只询问采用哪一种；日期可以继续待定。选择后先生成行程创建预览，确认前不会写入正式行程。

同一目的地的后续搜索会继承当前会话中明确指定的来源偏好，例如第一轮提到“小红书”，下一轮只说“搜索开封四日游”时仍会优先小红书。来源偏好不会跨会话或自动保存为长期个人偏好；切换目的地或明确排除平台会更新它。

“查看我的偏好”“记住，以后优先公共交通，轻松节奏”“忘记所有偏好”可管理长期默认，也可以在偏好面板操作。不同网页会话的聊天、附件和行程隔离；**同一本地使用者明确保存的长期偏好可跨网页会话应用**。QQ 与 Web 的偏好不互通。更新默认不会自动重写已保存行程。

## 5. 数据与提醒边界

### 删除会话及关联数据

会话列表旁的垃圾桶按钮，以及当前会话标题栏的垃圾桶按钮，都会先打开确认弹窗。确认后，该会话立即停用，并清理聊天记忆、附件、文档、行程、提醒、定时查询、规则监测、任务和通知。进行中的请求不能在删除后重新写回结果。

弹窗显示关联数据数量，并明确提示不可恢复。点击“取消”不会删除数据。删除其他会话不会清空当前会话的草稿；同源标签页会同步删除状态，其他浏览器在下一次同步时发现该会话已不可用。

删除有三个可见结果：

- **正在清理关联数据**：已停止该会话的任务和提醒，文件及记录正在清理。关闭网页不会中断后台清理。
- **清理尚未完成**：可能有文件占用或路径问题，会话保持停用。解除占用后点击“重试清理”；失败状态也会在重新打开网页时显示。
- **会话及关联数据已删除**：清理完成。系统不提供回收站，只保留不含正文、标题或附件路径的最少删除标记。

其他会话仍引用的共享图片会保留；QQ 数据、模型配置和公共规则缓存不受影响。已经发出的外部接口请求无法撤回，既有费用、你另存的文件和手工备份也不会随会话删除。

后台重启后会继续尚未完成的 pending／cleaning 作业；已明确失败的作业保留提示，由用户点击重试。删除不是磁盘取证级擦除。

### 保存和运行范围

QQ 与 Web 复用代码，但默认数据库和附件相互独立。网页不会自动读取旧 QQ 会话，不会发送到 QQ 群。项目 `data/` 已被 Git 忽略，其中的 `data/web/` 不应提交。

本地模式没有多人账号系统。不同浏览器窗口都属于同一个本地使用者；会话用于隔离上下文，不用于隔离同一电脑上的不同人。接口有会话 Cookie、CSRF、Host／Origin 校验，仍只用于本机，不可直接暴露到公网或局域网。

提醒与定时任务需要后端持续运行。新通知到达时，打开的网页会显示可点击的页面内提示，并同步更新“旅途通知”未读数；页面关闭时结果仍会写入站内通知。电脑休眠、关机或后端停止时暂停执行。恢复后的补发遵循原业务时效规则，并显示原定与实际时间。超过 24 小时补发窗口的个人提醒会自动清理，不再长期停留在提醒列表；提醒类站内通知保留 24 小时，其他旅途通知最多保留 7 天。本轮不提供操作系统级推送。

资料遵循现有留存策略：聊天／事件默认 30 天、预约和图片默认 90 天，文档默认不自动过期；网页未绑定消息的上传在一天后可清理。消息历史不是永久归档。备份时先停止 Web 服务，再整体复制 Web 数据目录，避免只复制活动数据库而遗漏 WAL 或附件。

本轮保留了端口、数据根目录、静态构建和无浏览器启动选项；尚未进行 Docker 构建或跨平台容器部署验收。现有缓存路径的完整容器迁移仍需后续验证。

## 6. 开发与检查

后端终端：

```powershell
$env:WEB_DEV = 'true'
$env:WEB_OPEN_BROWSER = 'false'
python run_web.py
```

前端终端：

```powershell
cd frontend
npm run dev
```

访问 `http://127.0.0.1:5173`。Vite 把 `/api` 和 `/health` 代理到后端 8080；若后端开发端口改动，应同时修改代理目标。正式本地模式不需要 `WEB_DEV`。

离线检查：

```powershell
python -X utf8 -m unittest discover -s tests -q
python -X utf8 scripts/evaluate_retrieval.py --output evals/retrieval-v2-local.json
cd frontend
npm test
npm run build
```

真实模型／高德检查：

```powershell
python -X utf8 scripts/smoke_web.py
```

该脚本使用临时数据，通过 Web API 验证天气、交通、行程、文档和提醒取消，不接入 QQ。会消耗已配置接口的正常调用额度；测试数据库在结束时销毁，不留下正式提醒。

`/health/live` 表示进程能响应；`/health/ready` 检查数据库和关键后台任务是否存活。后台任务由既有监督器重启，但存活不代表所有外部接口健康。“本地空间状态”展示后台状态和队列，“服务配置”展示按用途模型用量；两者都不展示密钥、提示词或聊天正文。缓存 token 和估算费用仅采用供应商实际返回及用户配置费率。

## 已保存行程的偏好调整

在原行程会话里，可以直接补充“希望轻松一些，尽量步行或公交地铁，少打车”等要求。系统会关联已保存行程，保留城市和日期，生成修改预览；回复“确认行程修改”后才保存。存在多份行程时，会先询问修改目标。

本次行程要求不会自动写入长期偏好。单独说“记住，以后默认轻松节奏”只修改长期默认；同时明确要求记住并调整当前行程时，预览会列出两项变更，确认后一起保存。

可以在同一句中补充节奏、交通、住宿和预算，例如“轻松一点，优先步行或公交，酒店舒适些，每间每晚人民币 200–300 元”。不需要按固定标签说话。其他旅行安排要求也会以原话传给规划器。若只说“酒店 200–300”，系统会保存已经理解的整组要求，只追问预算币种和计价单位；补充后继续修改同一份行程。酒店结果是地点候选，实际房价、房量和舒适度仍需另行核实。

确认前可以继续补充品牌等要求，新预览会接续当前草稿。确认过期后，草稿需求仍可用于生成新预览，旧确认按钮不会恢复执行资格。若看到预览不可用，或希望恢复旧会话中待修改的要求，可发送“重新生成行程预览”，核对完整内容后再确认；多份行程时附上具体行程编号。页面遇到渲染异常会显示恢复入口，返回首页不会删除服务器会话。

支持用“10月1日到10月三日”等日期区间规划三天，不必再补充天数。修复详情与验证范围见 [行程偏好接续修复与验收](../itinerary-preference-context-fix-2026-09-20.md)。

## 7. 常见问题

查询或回答出现异常时，可直接点击**提问下面的“查看处理过程”**，查看中文结论和各环节时间线，再点击“复制诊断报告”交给维护者分析。不需要PowerShell或手动查事件键。查看记录不会重跑查询或产生模型费用；没有记录时无法据此确定原因。旧版后端需先重启才能使用新入口。

本地BGE的准备、评测结果及启用边界见[诊断与embedding升级说明](../diagnostics-embedding-delivery-2026-10-16.md)。默认仍保持关闭。

| 现象 | 处理 |
| --- | --- |
| 找不到前端页面或静态文件 | 在 `frontend/` 执行 `npm ci`、`npm run build`，再启动后端 |
| 8080 被占用 | 先确认是否已有实例；修改 `WEB_PORT` 后重启，前端开发时同步修改 Vite 代理端口 |
| 设置已保存但仍用旧模型 | 完全重启后端；检查进程环境是否覆盖项目 `.env` |
| 自然语言偏好不修改行程 | 检查模型配置及 `TRAVEL_SEMANTIC_MODE=execute`，在原行程会话补充要求，再确认预览 |
| 提醒未按时出现 | 确认后端持续运行，电脑未休眠；检查任务状态、站内通知及 `/health/ready` |
| 无法删除完附件 | 会话已停用；解除文件占用后点击“重试清理” |
| 模型返回无效结果 | 保留已有数据，补充说明后重试；用左侧“服务配置”检查模型是否支持工具调用与图片输入 |

针对研究转行程及追加偏好的真实接口回归，可运行 `python -X utf8 scripts/smoke_trip_context.py`；它使用临时 Web 数据，不修改正式行程。
