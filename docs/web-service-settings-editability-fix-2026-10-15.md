# Web 服务配置输入框锁定：分析与修复

日期：2026-10-15

## 问题定位

“模型与地图基础配置”包含 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL_ID`、`AMAP_API_KEY`。原代码中的锁定链路为：

1. `infrastructure/env_settings_store.py` 在模块导入时用 `START_ENV` 记录启动环境中的服务字段。
2. `EnvSettingsStore._effective` 将这些字段判为 `source=environment`，优先于项目 `.env`。
3. `status` 对环境来源返回 `editable=false`。
4. `frontend/src/SettingsPanel.tsx` 用 `disabled={busy || !field.editable ...}` 禁用输入框和清除按钮。
5. 即使在浏览器强行启用输入框，原保存方法也会因为字段存在于 `self.inherited` 而拒绝修改。

因此该问题需要同时修复前端交互、后端保存和重启加载。只删除前端的 `disabled` 会造成用户可以输入但无法保存；只允许写入 `.env` 又会被启动环境中的旧值覆盖。

本轮干净终端及直接调用 Conda `agent` Python 时，四项字段没有预置在环境中，未复现所有字段锁定；没有运行中的 8080 Web 实例可供检查。不能据此确定用户当时是由 PowerShell、IDE、环境激活脚本或预先加载 dotenv 注入配置。上述锁定条件已通过模拟真实启动环境的回归用例复现。

## 修复行为

- 启动环境来源的服务字段允许在设置页替换，固定 Tavily 搜索地址保持只读。
- 网页保存环境字段时，将替换值与非敏感的字段名称列表 `WEB_SETTINGS_OVERRIDE_KEYS` 一起原子写入项目 `.env`。
- 只对用户明确保存的字段记录 Web 覆盖；未修改字段继续采用原环境值。
- Web 启动先按原逻辑加载项目与父目录 dotenv，再应用明确记录的覆盖项。设置页和实际运行使用相同优先级。
- 替换密钥保持只写不回显；清除密钥时覆盖值为空，重启不会回退旧环境密钥。
- 覆盖名称经过允许列表验证，不能通过覆盖记录写入 `PATH` 等系统字段。
- 保持版本冲突检测、文件锁、Git 忽略检查、私有文件权限、CSRF 和原子替换。
- 更换模型地址仍要求重新输入用于新地址的 Key；前端在提交前提示，后端返回固定且不包含敏感输入的具体错误信息。
- 字段旁显示环境来源的保存含义、项目覆盖状态和待重启提示。旧后端返回只读字段时，界面明确提示更新并重启后端。

## 影响范围

修改涉及服务配置存储、Web 启动加载、配置保存 API 和设置组件。覆盖记录只在 Web 启动时应用；不更改系统环境、父目录文件或 QQ 的启动优先级。用户实际凭据和正式聊天数据库未被本轮测试修改。
