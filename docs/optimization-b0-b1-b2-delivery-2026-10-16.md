## 2. B0：诊断如何使用及其边界

新增 [ExecutionDiagnostics](../infrastructure/execution_diagnostics.py)，由 MemoryStore 初始化，并接入运行时已有的摘要/上下文回调。请求、通用任务准备、模型请求、工具回执和投递也写入同一事件时间线。

记录内容限于关联ID、状态、版本/哈希、长度、错误码、次数、耗时等允许字段。**不默认存储聊天、工具参数/正文、提示正文、密钥或完整模型回答。** 诊断写入采用短等待并捕获失败；它不改变业务成功/失败结果。删除Web会话会清理相应记录并阻止迟到重建；保留期沿用事件保留设置。

新增 [只读导出命令](../scripts/export_execution_timeline.py)：

~~~powershell
Set-Location E:\Agent\travel_agent
D:\anaconda3\envs\agent\python.exe -X utf8 scripts/export_execution_timeline.py --database data/web/travel_bot.db --event-key "实际事件键"
~~~

导出不会初始化数据库、调用模型、重放工具或投递消息。旧库若没有诊断表，返回空时间线；不存在的数据库直接报错，不创建空文件。模型调用数取当前可读取的调用明细，历史明细被清理后不能据此推断其曾经零调用；独立费用账本仍是消费核算依据。

诊断记录需要存在的 Inbox 或聊天事件作为归属依据；没有事件归属的直接工具/模型调用不会产生脱离生命周期的诊断记录。当前是最小时间线，不宣称已经覆盖所有领域仓库的事务细节，也没有加入可恢复私人正文的失败快照或通用历史重放器。

验收覆盖：真实装配的回调接线、同事件模型/工具关联、预算阻断、任务准备冲突、允许字段过滤、写入失败隔离、只读导出、保留期、会话删除和迟到写入。

## 3. B1：核心读取边界统一

### 3.1 重试位于 HTTP 请求边界

高德客户端在单次HTTP请求边界处理暂时失败，即时查询、定时查询及行程规划均复用。已知生产路径去掉外层重复重试；兼容测试/第三方服务仍保留原适配。成功地理编码不会因为后续天气接口失败而被重新请求。

无服务端等待提示时使用有界随机退避；有合法 Retry-After 时将其视为最早重试时间，显式0也能正确处理。超过30秒或任务剩余期限不足时不原地等待、不提前重试。定时任务可将长等待交给持久化队列；超过一天窗口的等待不继续安排。

HTTP超时服从剩余任务期限。取消或失去执行权时停止后续尝试；修复了重试期限检查未显式关闭SQLite连接导致的Windows文件占用。

### 3.2 跨恢复的检查点与次数

新增 http_read_attempts，按事件、HTTP路径和参数标识请求；同一物理读取含恢复最多尝试3次。成功返回使用现有 event_tool_results 保存检查点。换客户端或恢复任务仍复用成功读取，不通过重启重置失败次数；新的用户事件有独立额度。

这个3次上限针对同事件的同一路径和参数，不是整个业务只允许3个HTTP请求。工具逻辑尝试、模型调用、HTTP尝试与消息投递分别计量，不把各层 attempts 简单相加。HTTP成功检查点也不意味着其业务字段已通过最终校验。

新增表及检查点遵守任务写入约束、会话删除与保留清理；检查点中的业务数据不由诊断导出器回显。

### 3.3 结构化结果与定时任务

天气、预报和路线结果增加与展示文本分离的 payload；检查天气必要字段、预报条目以及路线有效距离/耗时。非法返回、权限、暂时故障、限流和无匹配结果保持不同含义。保留旧字符串接口供调用者逐步迁移，修正兼容错误文本中“429，请稍后”被误归为普通暂时错误的优先级。

定时查询使用结构化读取及同一Router；永久错误和已耗尽的请求不会再由Worker扩大重试。暂时长限流等待保留到 next_attempt_at。失败不创建成功业务任务，沿用现有失败通知和查询状态。

服务连通探测明确使用一次HTTP尝试，保持原探测边界。此次没有发送真实地图、搜索、提醒或QQ消息。

**仍待扩展：** Tavily/网页读取尚未迁移到相同的错误契约；所有工具输出的完整领域schema、更多取消/并发恢复交错和平台确认丢失场景也不因此视为完成。
