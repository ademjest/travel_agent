# 确认卡片白屏与草稿接续修复

日期：2026-09-21

## 结果

已修复确认预览读取临时发送缓存导致的白屏，并支持连续修改和过期草稿需求接续。前端生产文件已经重新构建。真实会话数据未被测试修改，本次修改尚未提交或推送到 GitHub。

## 改动

- 确认预览与任务版本一起存入任务快照，不随投递检查点清空。
- 旧任务按确切事件关联，从对话记录或已投递消息找回预览，不使用无关的“最新一条回复”。
- 前端校验预览类型，空值或无效值显示恢复提示；增加页面和卡片错误边界。缺少完整预览时，确认按钮及后端接口均禁止执行。
- 同一行程继续补充要求时，语义上下文和执行服务使用最新需求草稿。追加酒店品牌保留之前的舒适要求、预算、交通和节奏。
- 草稿需求不依赖 30 分钟确认有效期。过期后重新规划并生成新确认任务，仍核对已保存版本和关联提醒；已取消草稿不会恢复。
- 对旧实现产生的、未继承前轮约束的草稿，恢复同一用户、会话、行程基础版本的已校验增量。已遗漏要求的旧预览不能直接确认，需先重新生成。
- 新增“重新生成行程预览”命令。若已保存行程基础版本发生变化，明确要求重新核对，不自动套用旧版本。
- 在保存新预览前同时校验行程版本与草稿版本，避免模型运行期间被其他修改覆盖。
